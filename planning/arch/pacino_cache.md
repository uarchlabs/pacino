# pacino

`pacino` is the system emitted by `cgen` from the five JSON files in
`testcases/pacino`. It is a two level cache hierarchy: split L1
instruction and data caches over a banked unified L2 over a
behavioural memory, driven by two agents.

The emitted tree is `output/`. Every file in it is generated. The
numbers in this document are taken from the emitted packages and from
`output/logs/geometry.log`, which carries the derived geometry the
tool computed.

|----------------|------|------|--------|------------|

| line bits      | 512  | 512  | 512    | 512        |

`mem` has no downstream link, so it has no refill. Its package

### Word and beat widths

The internal word of a node is the data width of the link on its
upstream side. The beat is the data width of the link on its
downstream side.

| Derived      | l1i | l1d | l2  | mem |
|--------------|-----|-----|-----|-----|
| word bytes   | 4   | 4   | 32  | 32  |
| word bits    | 32  | 32  | 256 | 256 |
| words / line | 16  | 16  | 2   | 2   |
| beat bytes   | 32  | 32  | 32  | 32  |
| beat bits    | 256 | 256 | 256 | 256 |

Address units are bytes throughout. Each package states this once, as
`<Node>AddrUnitBytes = 1`, and derives every word count from it.

## 1.5 Address decomposition

Every cache node emits its own decomposition and the functions that
apply it. The rule is `offset + index + tag == pa_bits`, which leaves
a bank select no field of its own: where banks is greater than one,
the select is taken out of the index rather than added beside it.
With line interleaving the select sits immediately above the offset,
and the set index is what remains of the index above the select.

### l1i and l1d, 32 KiB, 8 way, 1 bank

| Field  | Range   | Bits | Shift | Mask       |
|--------|---------|------|-------|------------|
| offset | [5:0]   | 6    | 0     | 0x0000003f |
| index  | [11:6]  | 6    | 6     | 0x00000fc0 |
| tag    | [31:12] | 20   | 12    | 0xfffff000 |
| bank   | -       | 0    | -     | -          |

With one bank the set index is the index: `[11:6]`, 6 bits.

### l2, 512 KiB, 8 way, 2 banks, line interleaved

| Field  | Range   | Bits | Shift | Mask       |
|--------|---------|------|-------|------------|
| offset | [5:0]   | 6    | 0     | 0x0000003f |
| index  | [15:6]  | 10   | 6     | 0x0000ffc0 |
| tag    | [31:16] | 16   | 16    | 0xffff0000 |
| bank   | [6:6]   | 1    | 6     | 0x00000040 |
| setidx | [15:7]  | 9    | 7     | 0x0000ff80 |

Consecutive lines alternate banks. 512 sets in each of the 2 banks.

### mem, 1 GiB, direct, 8 banks, line interleaved

| Field  | Range   | Bits | Shift | Mask       |
|--------|---------|------|-------|------------|
| offset | [5:0]   | 6    | 0     | 0x0000003f |
| index  | [29:6]  | 24   | 6     | 0x3fffffc0 |
| tag    | [31:30] | 2    | 30    | 0xc0000000 |
| bank   | [8:6]   | 3    | 6     | 0x000001c0 |
| setidx | [29:9]  | 21   | 9     | 0x3ffffe00 |

2097152 sets in each of the 8 banks.

## 1.6 Package constants and functions

Each node emits `<node>_pkg.sv` holding its whole derived geometry.
The constant prefix is the node name in mixed case: `L1i`, `L1d`,
`L2`, `Mem`, `Ifu`, `Lsu`. The type and function prefix is the node
name in lower case.

Constants, shown with the `l1d` prefix:

```
L1dPaBits        L1dCapacityBytes  L1dLineBytes    L1dLineBits
L1dWays          L1dBanks          L1dSets         L1dSetsPerBank
L1dBytesPerWay   L1dOffsetBits     L1dIndexBits    L1dTagBits
L1dBankBits      L1dSetIdxBits     L1dWayBits      L1dOffsetLsb
L1dOffsetMsb     L1dIndexLsb       L1dIndexMsb     L1dTagLsb
L1dTagMsb        L1dSetIdxLsb      L1dSetIdxMsb    L1dAddrUnitBytes
L1dWordBytes     L1dWordBits       L1dWordsPerLine L1dWordIdxBits
L1dWordIdxLsb    L1dWordIdxMsb     L1dBeatBits     L1dBeatBytes
L1dBeats         L1dBeatIdxBits
```

Types:

```
l1d_addr_t  l1d_tag_t   l1d_set_t   l1d_way_t
l1d_line_t  l1d_word_t  l1d_beat_t
```

`l2` and `mem` add `l2_bank_t` and `mem_bank_t`, since their bank
field is not empty.

Functions:

| Function                         | Returns                        |
|----------------------------------|--------------------------------|
| `<n>_tag_of(a)`                  | tag field of an address        |
| `<n>_set_of(a)`                  | set index field                |
| `<n>_bank_of(a)`                 | bank select, banked nodes only |
| `<n>_offset_of(a)`               | byte offset within the line    |
| `<n>_word_of(a)`                 | word index within the line     |
| `<n>_line_base(a)`               | the address with offset zeroed |
| `<n>_line_addr(tag[,bank],set)`  | the line a tag and set stand for |

`l1i` and `l1d` take `(tag, set)`. `l2` and `mem` take
`(tag, bank, set)`.

The agent packages `ifu_pkg` and `lsu_pkg` carry no geometry. They
hold only the widths of the link they drive:

```
IfuAddrBits = 32   IfuWordBits = 32   IfuWordBytes = 4   IfuPaBits = 32
```

|-------------------|---------------|---------------|-----|-------------|
| tag_array         | inferred_sram | registered    | no  | no          |
| data_array        | inferred_sram | registered    | no  | no          |
| valid_bits        | flop_file     | combinational | no  | yes         |
| replacement_bits  | flop_file     | combinational | no  | yes         |

### l1d

| Array             | Kind          | Read port     | BE  | Reset clear |
|-------------------|---------------|---------------|-----|-------------|
| tag_array         | inferred_sram | registered    | no  | no          |
| data_array        | inferred_sram | registered    | yes | no          |
| valid_bits        | flop_file     | combinational | no  | yes         |
| dirty_bits        | flop_file     | combinational | no  | yes         |
| replacement_bits  | flop_file     | combinational | no  | yes         |

### l2

| Array             | Kind          | Read port     | BE  | Reset clear |
|-------------------|---------------|---------------|-----|-------------|
| tag_array         | inferred_sram | registered    | no  | no          |
| data_array        | inferred_sram | registered    | yes | no          |
| valid_bits        | inferred_sram | registered    | no  | no          |
| dirty_bits        | inferred_sram | registered    | no  | no          |
| replacement_bits  | inferred_sram | registered    | no  | no          |

`l2` declares `data_array_organization` `way_in_address` and
`way_access` `serial_tag_then_data`. `l1i` and `l1d` declare
`array_per_way` and `parallel`.

Because the `l2` valid bits are a memory and not a flop file, they are
not cleared by reset. The control walks the sets after reset and
clears them through the array's invalidate port. `l1i` and `l1d` clear
theirs in the reset branch, which is correct for a flop file.

### mem

| Array      | Kind       | Read port  | BE  | Reset clear |
|------------|------------|------------|-----|-------------|
| data_array | behavioral | registered | yes | no          |

The store is an associative array keyed by beat address, so only the
beats a run touches exist.

## 1.8 Replacement encodings

Each node emits its replacement encoding into its own package, as
tables or as functions, so control, testbench and tests read one
encoding.

### tree_plru, l1i and l1d, 8 ways

| Constant           | Value |
|--------------------|-------|
| `<N>ReplBits`      | 7     |
| `<N>ReplStates`    | 128   |
| `<N>ReplReset`     | 0     |

Two tables are emitted:

- `<N>ReplVictimTable[0:127]`, the victim way of every state.
- `<N>ReplUpdateTable[0:127][0:7]`, the state left by touching each
  way from each state.

Read through `<n>_repl_victim(state)` and
`<n>_repl_update(state, way)`.

### lru, l2, 8 ways

| Constant       | Value                          |
|----------------|--------------------------------|
| `L2ReplBits`   | 24                             |
| `L2RankBits`   | 3                              |
| `L2ReplReset`  | `{0,1,2,3,4,5,6,7}`, way 0 first |

The state is a rank per way, 3 bits each. Rank 0 is most recently
used, rank 7 is the victim. Read through `l2_repl_rank(state, way)`,
`l2_repl_victim(state)` and `l2_repl_update(state, way)`.

Out of reset both encodings put the victim at way 0, so a cold set
fills from way 0 upward whichever policy is configured.

## 2.4 TileLink bundles

the l2 upstream data interface presents `up_d_a_valid`.

Widths below use `S` for that link's `source_bits`, `K` for its
`sink_bits`, and the data bus width of 256 bits with a 32 bit mask.

## 2.7 The agent command port

An agent has no geometry, so its only other port is the command port
the testbench drives. It is the same shape on every agent, which is
what lets one set of testbench tasks drive all of them.

| Signal          | Width | Direction | Meaning                  |
|-----------------|-------|-----------|--------------------------|
| `cmd_go`        | 1     | in        | start a request          |
| `cmd_go_write`  | 1     | in        | 1 write, 0 read          |
| `cmd_go_addr`   | 32    | in        | byte address             |
| `cmd_go_wdata`  | 32    | in        | write data               |
| `cmd_go_wstrb`  | 4     | in        | one bit per byte         |
| `cmd_busy`      | 1     | out       | a request is in flight   |
| `cmd_done`      | 1     | out       | the request completed    |
| `cmd_rdata`     | 32    | out       | read data                |

## 2.8 The system top

`pacino_top` is the elaboration and simulation top. It instantiates
every node and wires every edge. Its own ports are the clock, the
reset and the command port of each agent, prefixed with the agent
name.

```
module pacino_top (
  input  logic        clk,
  input  logic        rstn,
  input  logic        ifu_go,        output logic        ifu_busy,
  input  logic        ifu_go_write,  output logic        ifu_done,
  input  logic [31:0] ifu_go_addr,   output logic [31:0] ifu_rdata,
  input  logic [31:0] ifu_go_wdata,
  input  logic [3:0]  ifu_go_wstrb,
  input  logic        lsu_go,        output logic        lsu_busy,
  input  logic        lsu_go_write,  output logic        lsu_done,
  input  logic [31:0] lsu_go_addr,   output logic [31:0] lsu_rdata,
  input  logic [31:0] lsu_go_wdata,
  input  logic [3:0]  lsu_go_wstrb
);
```

The agents are drivers and are not synthesizable, so this top is not
synthesizable either. The synthesizable part of the design is the
cache nodes, each of which is its own top with clock, reset and its
link ports and nothing else.

Reset is `rstn`, active low. The clock is `clk`, rising edge. Every
sequential process in the emitted design is posedge clocked.

```
output/
  Vars.mk                   tool variable set, included by every Makefile
  logs/                     emission, geometry, features, unconsumed
  pacino/                   the system: top, link packages, top testbench
  ifu/  lsu/                the agents
  l1i/  l1d/  l2/  mem/     the cache nodes
```

Each node directory holds `rtl/`, `tb/`, a Makefile and a `<node>.f`
filelist. The system directory adds `images/`, where a run writes its
memory images.

## 3.2 Modules per node

```
ifu   ifu
lsu   lsu
l1i   l1i  l1i_bank  l1i_ctrl  l1i_meta_array  l1i_data_array
      l1i_core_slv   l1i_mem_mst
l1d   l1d  l1d_bank  l1d_ctrl  l1d_meta_array  l1d_data_array
      l1d_core_slv   l1d_mem_mst
l2    l2   l2_bank   l2_ctrl   l2_meta_array   l2_data_array
      l2_up_i_slv    l2_up_d_slv   l2_down_mst
mem   mem  mem_up_slv
```

The shape is the same at every cache node. The node top holds the
interface adapters and the banks and arbitrates between them; each
bank holds a control, a metadata array and a data array. One adapter
is emitted per interface, named `<node>_<interface>_slv` or
`<node>_<interface>_mst` after its role. The adapter is where the
protocol lives; the control behind it sees one internal request
bundle and never sees which link it came from.

`l1d` and `l1i` have one bank, so their arbitration reduces to a
pass through. `l2` has two banks and two upstream interfaces and
arbitrates round robin, both for the banks between the slaves and for
the downstream link between the banks.

## 3.3 Packages

| Package         | Emitted in     | Holds                            |
|-----------------|----------------|----------------------------------|
| `cgen_tl_pkg`   | pacino/rtl     | the TileLink constant set        |
| `pe_port_pkg`   | pacino/rtl     | pe_port widths                   |
| `tl_l1i_l2_pkg` | pacino/rtl     | tl_l1i_l2 widths                 |
| `tl_l1d_l2_pkg` | pacino/rtl     | tl_l1d_l2 widths                 |
| `tl_l2_mem_pkg` | pacino/rtl     | tl_l2_mem widths                 |
| `ifu_pkg`       | ifu/rtl        | the link widths ifu drives       |
| `lsu_pkg`       | lsu/rtl        | the link widths lsu drives       |
| `l1i_pkg`       | l1i/rtl        | l1i geometry, types, replacement |
| `l1d_pkg`       | l1d/rtl        | l1d geometry, types, replacement |
| `l2_pkg`        | l2/rtl         | l2 geometry, types, replacement  |
| `mem_pkg`       | mem/rtl        | mem geometry and types           |

A node's filelist reads the shared packages first, then its own
package, then its modules, then its testbench. Order matters: a
package has to be read before the module that imports it.

## 3.4 Testbenches

| Testbench   | Top module   | Responder            |
|-------------|--------------|----------------------|
| `pacino_tb` | `pacino_top` | the `mem` node       |
| `l1i_tb`    | `l1i`        | `l1i_tb_mem`         |
| `l1d_tb`    | `l1d`        | `l1d_tb_mem`         |
| `l2_tb`     | `l2`         | `l2_tb_mem`          |
| `mem_tb`    | `mem`        | none, mem is terminal|
| `ifu_tb`    | `ifu`        | `ifu_tb_slv`         |
| `lsu_tb`    | `lsu`        | `lsu_tb_slv`         |

Every testbench includes `cgen_tb_tasks.svh`, the shared task set:
`cg_init`, `cg_tick`, `cg_check`, `cg_check_eq`, `cg_wait`,
`cg_reset`, `cg_report`, and the counters `cg_pass`, `cg_fail`,
`cg_cycle`, `cg_limit`. Nothing in it knows a protocol. Sampling is
on the negedge throughout, so the design's posedge updates have
settled before a testbench reads them.

The self checking tests are in `<node>_tests.svh` and
`pacino_tests.svh`, included inside the testbench module. They read
the node's own package, so a test cannot disagree with the design
about where an address field is.

The run away guard is a plusarg, not a configuration field:

```
./obj_dir/pacino_tb +cg_limit=200000
```

## 3.5 Memory images

The top level run writes memory images into `output/pacino/images`,
one per named point. `pacino_tb` takes four: `after_reset`,
`after_write`, `after_evict` and `final`.

The format is a text header followed by one line per beat the store
holds, address then data, both hex.

```
cgen-memimage 1
system pacino
node mem
point after_evict
addr_bits 32
data_bits 256
beat_bytes 32
line_bytes 64
entries 10
00450000 000000...00c0de0001
00450020 000000...00c0de0002
```

# 4. Build and run

## 4.1 Tool variables

`output/Vars.mk` is included by every emitted Makefile. Every recipe
invokes a tool through a variable and never by a bare name.

| Variable    | Value                                |
|-------------|--------------------------------------|
| `VERILATOR` | `$(CGEN_ROOT)/tools/bin/verilator`   |
| `MAKE`      | make's own value                     |
| `RM`        | `rm`                                 |
| `MKDIR`     | `mkdir`                              |
| `ECHO`      | `echo`                               |

`CGEN_ROOT` must be set. `Vars.mk` errors out if it is not. It is the
one emitted file whose contents vary with the command line; every
other emitted file is byte identical between two runs of one
configuration.

## 4.2 Targets

From `output/pacino`:

| Target  | Does                                            |
|---------|-------------------------------------------------|
| `lint`  | lints every emitted file, units then the system  |
| `build` | builds the top level testbench                   |
| `run`   | builds and runs the top level testbench          |
| `units` | builds and runs every unit testbench             |
| `all`   | lint, then the top level, then the units         |
| `clean` | removes object and image directories everywhere  |

Each node directory carries the same target set for itself.

```
export CGEN_ROOT=/path/to/cachegen
make -C output/pacino all
make -C output/pacino run TRACE=1
make -C output/l1d run
```

`TRACE=1` adds `--trace` to the Verilator command line. `PLUSARGS`
passes arguments to the simulation binary. Both are simulation
control and neither appears in the configuration.

## 4.3 Emission record

`output/logs` carries four generated logs.

| Log              | Records                                          |
|------------------|--------------------------------------------------|
| `emission.log`   | what this run emitted: 6 nodes, 5 edges, 83 files |
| `geometry.log`   | the derived geometry, node by node                |
| `features.log`   | every declared feature and the test that covers it |
| `unconsumed.log` | every field no stage read                        |
