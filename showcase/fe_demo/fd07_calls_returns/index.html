    fd07_calls_returns: Calls and Returns¶

    Open waveform

    Runs Surfer in the browser, with nothing to install. The signal setup takes a few seconds to apply.

    1. Introduction¶

    fd07_calls_returns (FD-7) runs a loop of 8 passes. Each pass makes nested calls, then a recursion four calls deep from one call site, then a coroutine switch by two return-calls.

    The return address stack (RAS) pushes a call's return address and pops it for a return at p2, which supplies the return's target. A recursive call whose return address matches the top of the stack increments that entry's count, spec_rctr, instead of allocating an entry. A return-call pops and then pushes in one operation.

    The RAS supplies the target of 64 of the 80 retired returns and return-calls. The result line in the log file reports that count, the p2 operations, and the highest recursion count.

    This scenario runs in the 1-prediction slot Pacino configuration, NUM_PRED_SLOTS=1.

    3. The program¶

    The program is written by the task prog_fd07 in programs/fd07_calls_returns.svh. The code consists of a short prologue, then a loop of 8 passes starting at top, and a short epilogue.

    Each pass calls f1, which calls f2. It then calls f, which calls itself four times from the one call site at 0x8000_080A. It then calls B through x5, and B and the main code switch by the return-calls B1 and A1. B returns through x5 at B2, and the back edge at 0x8000_002A returns to top.

    The program runs in machine mode with translation off, the addresses are physical. The program starts at the reset vector, RESET_VECTOR = 0x8000_0000 (bp_defines_pkg.sv).

    Address      Label  Instruction             Purpose               Block  Pos
0x8000_0000         c.addi a0, 1            ; prologue

0x8000_0806         bne    x6, x0, f+16     ; taken at the bottom 800    3
0x8000_080A         jal    x1, f            ; recursive call      80A    0
0x8000_080E         c.addi a0, 1            ; after a return      80E    0
0x8000_0810         ret                     ; return from f       80E    1

0x8000_0A00  B:     c.addi a0, 1            ; filler              A00    0
0x8000_0A02         addi   t0, t0, 1        ; filler              A00    1
0x8000_0A06  B1:    jalr   x1, 0(x5)        ; return-call         A00    3
0x8000_0A0A         c.addi a0, 1            ; filler              A0A    0
0x8000_0A0C         addi   t0, t0, 1        ; filler              A0A    1
0x8000_0A10  B2:    jalr   x0, 0(x5)        ; return              A0A    3

    Block is the low bits of the start address of the prediction block that holds the instruction, and Pos is its halfword position from that start. With one prediction slot, each block holds one branch. The ret at 0x8000_0810 is also predicted in a block of its own at 0x8000_0810, position 0, when the branch at 0x8000_0806 is taken.

    The c.addi and addi instructions do no useful work. Their purpose is to mix 16-bit and 32-bit instructions and to separate the branches.

    The program writer types each branch from its link registers, x1 and x5. A jal with a link register as rd is a DIRECT_CALL. A jalr with a link register as rs1 and not as rd is a RETURN, and one with unequal link registers as rd and rs1 is a RETURN_CALL. The directions and targets are chosen by the program writer and resolved by the modeled backend, and the register operands play no part in them.

    Each pass retires 8 direct calls, 8 returns and 2 return-calls. The 8 returns are f2's, f1's, 5 from f and B2. Over 8 passes that gives 80 retired returns and return-calls, the total the monitor's count is out of.

    4. Walkthrough¶

    Cycle numbers below are events in section 5; each event is a marker in the waveform.

    4.1 Predicting the returns¶

    The RAS holds two stacks. The speculative stack has 16 entries and changes at p2, and it is empty when TOSR equals BOS. The commit stack has 32 entries, changes as calls and returns retire, and holds one entry per call with no count.1

    A slot of the p2 group goes to the RAS when it holds a branch of a valid block and no earlier slot of the block is taken.2 A call pushes its fall-through address. If that address equals the top entry's, the entry's spec_rctr is incremented and the pointers do not move. Otherwise a new entry is allocated at TOSW.3 A return pops: a non-zero count is decremented and TOSR holds, and a count of 0 sends TOSR to the entry below.4 A RETURN_CALL pops and then pushes.5 The pop supplies the slot's target with pred_src PRED_RAS at p2, and a return slot from the uBTB takes the top of the stack at p1.6

    A commit moves BOS to the TOSR its block left.7 A pop of an empty speculative stack reads the top of the commit stack and changes neither stack.8 A backend redirect restores TOSR, TOSW and BOS from a snapshot and leaves the entries and their counts as they are.9

    The monitor's count of 64 divides across the passes as follows.

    pass     returns   from the RAS   not from the RAS
0        10        2              7 not yet in the FTB; f's last return
1        10        8              f1's return; f's last return
2 to 7   10 each   9 each         f's last return

    In pass 0, no return reaches p2 before cyc 162 (event 7), and the backend corrects each return the FTB does not hold yet. In pass 1, f1's return at cyc 248 finds both stacks empty, so it takes the FTB's target with pred_src PRED_FTB.

    F's last return is mispredicted in all 8 passes, for one reason. The recursive call at 0x8000_080A pushes 0x8000_080E each time. The first allocates an entry and the other three increment it, so the blocks of all four calls leave TOSR on that entry. When the first of them commits, BOS moves to the entry, and the speculative stack is empty.

    Pass 6 shows the sequence. Entry 9 is allocated at cyc 578, and its count reaches 3 at cyc 589. The first recursive call commits at cyc 588, which moves BOS to 9. The returns reach p2 from cyc 594 with the stack empty, so each takes the top of the commit stack, 0x8000_080E, and the count of entry 9 stays at 3. The first four returns are correct. The fifth returns to main at 0x8000_0018, but no return has committed yet, so the top still reads 0x8000_080E. The backend corrects it at cyc 606. The figure below shows these cycles.

    The redirect to 0x8000_0018 is at cyc 172 in pass 0 (event 9), at cyc 294, 361, 427, 494, 550 and 606 in passes 1 to 6, and at cyc 662 in pass 7 (event 15).

    The other returns come from the speculative stack, where the calls are recent enough that the stack is not empty. The first is f2's in pass 1 at cyc 246 (event 10), which pops 0x8000_050A with TOSR at 2 and BOS at 1.

    The recursion count differs by pass.

    pass   entry    highest count   count rises at cyc
0      1        4               131 to 137
1      4        4               267 to 273
2      11, 12   1               325, 341
3      3        3               392 to 400
4      10, 11   1               458, 474
5      2        3               525 to 533
6      9        3               581 to 589
7      0        3               637 to 645

    Four recursive calls give a count of 3. The count of 4 in passes 0 and 1 comes from a fifth call on a predicted path. At the bottom of the recursion the branch at 0x8000_0806 is predicted not taken, so the path calls f again and the count reaches 4 at cyc 137 (event 4). The backend redirects to 0x8000_0810 at cyc 139 (event 5). The redirect does not change the count, so entry 1 holds 4 until the entry is reallocated at cyc 374 (event 14). Pass 3 also makes a fifth call, at cyc 404, but the stack is empty by then, so that call allocates an entry and the count stays at 3.

    In passes 2 and 4, a p3 redirect sends the path to 0x8000_0810 after the second recursive call, at cyc 327 and 460. A pop then decrements the count, the first at cyc 330 (event 13), and the backend redirects to 0x8000_080A at cyc 335 and 468. The recursion continues in a new entry. The pops at cyc 330, 343, 463 and 476 are the only ones in the run that decrement a count.

    The first return-calls at p2 are on a predicted path that is later redirected. The p3 redirect at cyc 252 leads to B1 at cyc 256 (event 11), and the backend redirect at cyc 261 removes it. The return-calls of the retired path first reach p2 in pass 1. At cyc 298 (event 12), B1 pops 0x8000_001E and pushes 0x8000_0A0A. At cyc 300, A1 pops 0x8000_0A0A and pushes 0x8000_0028. At cyc 302, B2 pops 0x8000_0028.

    The backend reports 25 mispredictions in the run: 12 in pass 0, 3 in pass 1, 2 each in passes 2, 3 and 4, 1 each in passes 5 and 6, and 2 in pass 7. The single redirects of passes 5 and 6 are f's last return. Pass 7 adds the back edge falling through at cyc 683 (event 16).

    4.2 The stack operations in the waveform¶

    The waveform group ras shows the pointers, the entries and the p2 operation. bpu_slot_p2.[0].target is the address the pop supplies.

    At cyc 128 (event 2), u_bpu.w_ras_pred_val_p2.[0] is asserted with u_bpu.w_br_type_p2.[0] DIRECT_CALL and u_bpu.r_pc_p2 at 0x8000_080A. By cyc 130, u_ras.tosr reads 1 and u_ras.tosw reads 2. u_ras.spec_rctr.[1] reads 1 at cyc 131 (event 3) and steps to 4 at cyc 137 (event 4), while tosr holds.

    At cyc 162 (event 7), tosr and bos both read 1 and u_ras.p2_pre_empty.[0] is asserted. bpu_slot_p2.[0].target is 0x8000_080E with pred_src PRED_RAS, the value of u_ras.commit_top_addr in the ras_commit group.

    At cyc 246 (event 10), tosr reads 2 and bos reads 1, and p2_pre_empty.[0] is deasserted. The target is 0x8000_050A, the value of u_ras.spec_ret_addr.[2].

    At cyc 298 (event 12), w_br_type_p2.[0] is RETURN_CALL at r_pc_p2 0x8000_0A00, and tosr and tosw read 5 and 6. They read 6 and 7 at cyc 300, so the pop and the push of the one operation show as one step.

    From cyc 594 to cyc 601, in pass 6, tosr and bos both read 9, p2_pre_empty.[0] is asserted on each pop, spec_rctr.[9] holds 3, and commit_top_addr holds 0x8000_080E. The backend's redirect to 0x8000_0018 is at cyc 606, in the backend group.
