    fe_top Connectivity Inventory¶

    This file records the net-level connectivity of fe_top. The block diagrams docs/fe_block.svg and docs/fe_pipe.svg use it as the reference for connections between blocks.

    Section 3 lists the nets between instances, section 4 lists the fe_top boundary ports, section 6 lists the predictors inside bp_cluster, and section 7 describes the page table walker that the testbench places beside fe_top.

    1. Notation¶

    Notation:

    • W bits is the packed width. N x W bits is an unpacked array of N elements, each W bits wide.
    • from is the instance output that drives a net, and to is the instance input that reads it.
    • bind fe_top.sv:L is the line of the port connection.
    • A file name without a directory is one of the module files listed in section 2.1.

    fe_top is a purely structural module containing 7 instances, 141 nets between instances (section 3) and 75 top-level ports (section 4).

    4. The fe_top boundary¶

    The ports are declared at fe_top.sv:96-217 and grouped as FE-17 (planning/arch/fe_decisions.md:1378) and FE-20 (planning/arch/fe_decisions.md:1445) group them; fe_top.sv:29-60 restates the grouping. -> is a fe_top input read by an instance input; <- is a fe_top output driven by an instance output.

    FE-17 counts two groups that cross (translation and backend) and says the instruction path is not a boundary group: what crosses is the L1I's l2-side port mem, a topology edge. FE-20 adds three inward groups (csr, config, maintenance) and one outward dependency, the ibuf read ready. The RTL carries all of them as fe_top ports; the L1I's mem port is section 4.8. Two outputs are in no group (section 4.12).

    bkend_ftq_redir_val is the one fe_top net with two readers: the FTQ and the ibuf clear (fe_top.sv:44-45, IBUF-13).
