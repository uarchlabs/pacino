    fd02_steady: Steady-State Prediction and Fetch¶

    Open waveform

    Runs Surfer in the browser, with nothing to install. The signal setup takes a few seconds to apply.

    1. Introduction¶

    fd02_steady (FD-2) runs 2 KB of straight-line code. There are no branches, therefore every uBTB lookup will miss. Consequently the p1 prediction address returned is the fall-through address, the lookup PC + 32 bytes returned in p1 on bpu_pred_pft_p1.

    In this scenario the FTQ allocates one entry per cycle. The front end reaches steady state at cyc 20, when decode begins delivering eight instructions per cycle.

    The simulation executes 513 instructions, 512 addi and the halt jal. Once these instructions have retired the front end fetches for 100 more cycles, and the simulation finishes.

    3. The program¶

    Source: programs/fd02_steady.svh, task prog_fd02.

    The RESET_VECTOR parameter is 0x8000_0000.

    0x8000_0000   addi t0 x 512      32-bit instruction
...           (addi)             2048 bytes in 32B prediction blocks
0x8000_0800   jal x0,0           halt, loop to self

    4. Operation¶

    Signal paths are as given in section 6. Event numbers refer to section 5.

    4.1 Prediction and FTQ allocation¶

    Reset is deasserted at cyc 0 (event 0). No hold condition is active, so ftq_pred_val_p0 is asserted and the FTQ issues its first prediction request, with ftq_pred_pc_p0 = 0x8000_0000 and ftq_pred_idx_p0 = 0.1

    The BPU returns the p1 prediction at cyc 1 (event 1), with bpu_pred_val_p1 asserted. The uBTB lookup misses: u_bpu.r_ubtb_blk_p1.hit and bpu_pred_slot_p1.[0].slot_valid are deasserted, and bpu_pred_pft_p1 is the lookup PC + 0x20. u_ftq.w_ok_pred_p1 asserts when bpu_pred_idx_p1 matches the outstanding request, and this writes the prediction into the FTQ entry.2

    In the same cycle, bpu_pred_pft_p1 drives ftq_pred_pc_p0 combinationally. This is the zero-bubble path: the next request is presented in the cycle in which the current prediction is formed, so no idle cycle separates consecutive prediction blocks.3 As a result, ftq_pred_pc_p0 increments by 0x20 per cycle and u_ftq.w_ok_pred_p1 remains asserted from cyc 1. u_ftq.u_npc.w_hold, ftq_full, u_ftq.w_ok_slot_p2 and u_ftq.w_ok_slot_p3 remain deasserted throughout.

    4.2 Instruction fetch¶

    The FTQ presents entries to the IFU from cyc 3. ftq_ifu_req_val and ftq_ifu_req_rdy are asserted, so one block transfers per cycle, with ftq_ifu_next_pc equal to ftq_ifu_start_pc + 0x20.

    Each block fetch covers 34 bytes: the 32-byte block plus one halfword, for a 32-bit instruction that crosses the block end. A block that starts in the upper half of a 64-byte L1I line therefore requires two lines, and it reuses the first if the previous block requested it. Block 0x8000_0000 requests line 0x8000_0000 at cyc 4 and block 0x8000_0020 requests line 0x8000_0040 at cyc 5. Thereafter, only the upper-half blocks issue requests, so ifu_l1i_req_val asserts on odd cycles from cyc 7. l1i_ifu_rsp_val first asserts at cyc 16 and then asserts every second cycle.5

    4.3 Delivery to decode¶

    The block at 0x8000_0000 reaches the IBUF at cyc 18 (event 2). ifu_ibuf_val is asserted and u_ibuf.w_n_pres is 8, so all eight tb.pd_out.[i].valid lanes are asserted. tb.dec_ibuf_rdy is asserted, so u_ibuf.w_n_pop is also 8. Each block passes through the IBUF without accumulating, and u_ibuf.r_count remains 0.

    No block is delivered at cyc 19, because block 0x8000_0020 also requires line 0x8000_0040, which is returned at cyc 18 and is readable from cyc 19. From cyc 20 (event 3) through cyc 82, one full bundle is delivered every cycle, with tb.pd_out.[0].start_pc incrementing by 0x20. This is the steady state: one line every two cycles, at two blocks per line and eight instructions per block, delivers eight instructions per cycle.

    Predecode writes back to the FTQ one cycle after each bundle, with ifu_ftq_pdwb_val asserted and ifu_ftq_cfi_val deasserted until the halt. u_ftq.w_commit_ptr advances one entry per cycle from cyc 23.

    4.4 Halt¶

    Prediction continues past the halt JAL, which has not been trained into the BPU. ftq_pred_pc_p0 reaches 0x8000_0800 at cyc 64 and continues along the fall-through path to 0x8000_0a60.

    The halt block reaches decode at cyc 83 (event 4). u_ibuf.w_n_pres is 1, so only lane 0 is valid. At cyc 84 the predecode writeback identifies the JAL: ifu_ftq_cfi_val and ifu_ftq_mis_val are asserted, ifu_ftq_mis_pos is 0 and ifu_ftq_target is 0x8000_0800. This asserts u_ftq.w_pd_redir_val, u_ftq.w_redir_val and ftq_ifu_flush_val, and redirects ftq_pred_pc_p0 to 0x8000_0800.

    The last instruction has retired by cyc 84 (event 5), so tb.dec_ibuf_rdy deasserts.4

    5. Events¶

    # cyc Event Other
    0 0 reset released (tb.rstn); the FTQ requests 0x8000_0000 the same cycle fast init
    1 1 first p1 prediction the FTQ accepts; one in every cycle from here to the end of the simulation uBTB miss, the next 32-byte block
    2 18 first full decode bundle, the block at 0x8000_0000: all eight lanes of pd_out valid
    3 20 second full bundle, the block at 0x8000_0020; one full bundle in every cycle from here to cyc 82
    4 83 the halt block reaches decode, one instruction in lane 0 0x8000_0800
    5 84 the last instruction retires
