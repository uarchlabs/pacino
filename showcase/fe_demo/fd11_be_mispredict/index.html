    fd11_be_mispredict: Backend Mispredict¶

    Open waveform

    Runs Surfer in the browser, with nothing to install. The signal setup takes a few seconds to apply.

    fd11_be_mispredict is the FD-11 demonstration scenario. It is a demo, not a verification test. Each of 32 passes runs a conditional with a pseudo-random outcome, then a call and its return. The predictors cannot learn the conditional, so the backend resolves it against the prediction and redirects. The redirect squashes the younger FTQ entries, flushes the IFU, rolls back and corrects the global history, restores the RAS pointers from the entry's snapshot, and fetch restarts at the corrected PC. The run passes if a backend mispredict redirect is followed by a fetch that starts at the redirect PC.

    The scenario runs on the one-slot model (Makefile SCEN_2S, DOC-006). A recorded run:

    -I: fd11_be_mispredict: PASS, backend mispredict redirects 21,
    fetches at the redirect address 21, history rollbacks 82, RAS restores 82,
    cyc 480

    1. The program¶

    Source: programs/fd11_be_mispredict.svh, task prog_fd11 (line 21). Addresses derived from the source (RESET_VECTOR 0x8000_0000):

    0x8000_0000          mixed(3)
top = 0x8000_0008    c.addi
0x8000_000A   A:     bne x6,x0,0x8000_0010   taken when the LFSR bit is 1
0x8000_000E          c.addi                  skipped when A is taken
0x8000_0010          jal x1,fn               call, link 0x8000_0014
fn = 0x8000_0400     mixed(2); ret           return to 0x8000_0014
0x8000_0014          c.addi
0x8000_0016   E:     bne x6,x0,top           back edge, passes 0..30
0x8000_001A          mixed(3)
                     jal x0,0                halt (demo_go -> W.halt)
    • A's direction is one bit of the writer's 16-bit Galois LFSR, taps 0xB400, seed 0xACE1 (lfsr_bit, rtl/core/frontend/fe_top/tb/models/fe_tb_writer.svh:523). Computed outside the testbench from that seed, the 32 bits are 10000111001000110100011011011100: 15 taken, 17 not taken.
    • Each pass writes the same bytes (W.wp = top); cskip (fe_tb_writer.svh:502) writes the skipped c.addi dry when A is taken. The backend retires against the writer's expected stream, so x6 is never read.

    2. Why the program produces the behavior¶

    1. The backend redirect. The in-order backend resolves each branch against the FTQ's prediction and on a difference raises bkend_ftq_redir_val with bkend_ftq_redir_cause RC_MISPREDICT (2'b00, rtl/core/frontend/bpu/rtl/bp_structs_pkg.sv:126) and the correct PC.
    2. Priority. In the FTQ's p0 arbiter a backend redirect is arm 1 and outranks every BPU and predecode redirect (rtl/core/frontend/ftq/rtl/ftq_npc.sv:317-328); the next p0 request is bkend_redir_pc.
    3. Squash and flush. Every redirect raises ftq_ifu_flush_val (rtl/core/frontend/ftq/rtl/ftq_ifu.sv:352), dropping the IFU's younger blocks.
    4. History rollback and correction. A redirect with a cause other than RC_UNSPEC raises ftq_rollback_val (ftq_npc.sv:399). bp_history restores the pointer from the named entry's checkpoint; with rollback_corr set it writes the corrected outcome bits (rollback_n, rollback_tkn, rollback_pbit) and advances past them (rtl/core/frontend/bpu/rtl/bp_history.sv:43-58).
    5. RAS restore. ras_restore_val is ftq_rollback_val (rtl/core/frontend/ftq/rtl/ftq.sv:518): the RAS restores TOSR, TOSW and BOS from the entry's snapshot (ras_restore_snapshot, port rtl/core/frontend/bpu/rtl/ras.sv:65-72, writes lines 808-811 and 834-835). bp_cluster drops the restore when the redirect is the block's own p2 or p3 redirect (w_ras_restore_val, bp_cluster.sv:1402).

    From the run (out/fd11_be_mispredict/fd11_be_mispredict.fst, bkend_ftq_redir_pc at each bkend_ftq_redir_val): 18 of the 21 redirects are A, 8 to 0x8000_0010 (taken) and 10 to 0x8000_000E (not taken); one is the return at cyc 49 (to 0x8000_0014), one the back edge at cyc 60, cold (to 0x8000_0008), and one the loop exit at cyc 471 (to 0x8000_001A). Every one has cause 0 (RC_MISPREDICT).

    3. What the monitor counts¶

    Every cycle (tb/fe_demo_mon.svh:488-501):

    n_be_misp    bkend_ftq_redir_val with cause RC_MISPREDICT; it arms a
             wait for the next fetch, with the redirect PC
n_be_fix     the first FTQ fetch after it (ftq_ifu_req_val and
             ftq_ifu_req_rdy, no flush that cycle) whose
             ftq_ifu_start_pc is the redirect PC
n_rollback   ftq_rollback_val
n_ras_rest   ras_restore_val

    The proof (tb/fe_demo_proofs.svh:100) is n_be_fix > 0. tb_fe_demo.sv:160 also requires the whole stream to retire with no errors.

    4. Reading the numbers¶

    • 21 of 21 backend mispredicts were followed by a fetch at the corrected PC.
    • rollbacks and RAS restores are equal because the two are one net (ftq.sv:518). They count every redirect the FTQ takes with a cause, from any arm: backend, predecode, p3 and p2. So 82 includes the 21 backend redirects and 61 from the other arms. RAS restores counts ras_restore_val at the FTQ, before bp_cluster drops the restore of a block's own p2 or p3 redirect.
    • Departure from FD-11 in planning/showcase/fe_demo_scenarios.md: the spec's program is "a data-dependent branch the predictors get wrong". The build's branch has a pseudo-random outcome chosen by the writer (tb_fe_top misp_call); no data dependence is modeled. The proof matches the spec.

    5. Waveform¶

    The saved view is waves/fd11_be_mispredict.sucl, which make view S=fd11_be_mispredict opens in Surfer. Look at:

    • backend group: bkend_ftq_redir_val with bkend_ftq_redir_cause RC_MISPREDICT, bkend_ftq_redir_idx and bkend_ftq_redir_pc.
    • ftq_ifu group: ftq_ifu_flush_val the same cycle, then ftq_ifu_req_val with ftq_ifu_start_pc equal to the redirect PC.
    • bp_history_ras group: ftq_rollback_val, ftq_rollback_idx, ftq_rollback_corr, bpu_ghist_ptr stepping back, and ras_restore_val with ras_restore_snapshot.tosr, .tosw, .bos.
    • bp_cluster_p0 group: the next ftq_pred_pc_p0 is the redirect PC.

    6. Events¶

    cyc Event Other
    0 reset released (tb.rstn); the FTQ requests fast init
    0x8000_0000 the same cycle
    19 first history rollback (ftq_rollback_val), a predecode
    with its RAS restore (ras_restore_val) redirect
    20 first misprediction of A taken; redirect to pass 0, backend
    0x8000_0010
    49 the return mispredicted; redirect to 0x8000_0014 backend
    53 fetch restarts at 0x8000_0014: the FTQ presents ftq_ifu_start_pc
    a block from the redirect address to the IFU
    60 the back edge mispredicted, cold; redirect to backend
    0x8000_0008
    86 first misprediction of A not taken; redirect to backend
    0x8000_000E
    471 the loop exits: the back edge falls through, a pass 31, backend
    misprediction; redirect to 0x8000_001A
