    fd12_training: Predictor Training¶

    Open waveform

    Runs Surfer in the browser, with nothing to install. The signal setup takes a few seconds to apply.

    1. Introduction¶

    fd12_training (FD-12) shows resolved branches initiating update requests routed to the respective predictor based on branch type. It also illustrates the operation of the single ported FTB.

    The scenario runs an outer loop of 14 iterations, containing an inner loop of 6 iterations. The outer loop includes:

    1. an always-taken conditional
2. an indirect jump
3. an indirect call and its return.

    The inner loop includes a backward branch executing the stated 6 iterations.

    This code then results in all predictors receiving illustrative updates.

    Each executed branch is resolved by the backend, converted by ftq_upd_conv into per-predictor updates, and presented to the cluster.

    An FTB update is a read-modify-write and occupies the single FTB read port for one cycle. Prediction lookups use the same port at p1. To avoid the conflict, the FTQ stalls its prediction request in the cycle before each FTB update.

    The result line in the log file reports the update count for each predictor and the number of FTQ prediction request stall cycles.

    This scenario runs in the 1-prediction slot Pacino configuration, NUM_PRED_SLOTS=1.

    3. The program¶

    The program is written by the task prog_fd12 in programs/fd12_training.svh. The code consists of an arbitrary prologue, then the outer loop of 14 passes starting at otop, and a short epilogue. The inner loop of 6 passes starts at itop.

    Each outer pass runs the inner loop, then the always-taken beq (B:), the indirect jump (J:), the indirect call (K:) to fn and its return, then the outer loop branch (O:) returning to otop.

    The inner loop branch (I:) and the outer loop branch (O:) are taken on every execution except the last iterations.

    The beq (B:) operand selection, x0 and x0, results in the branch always being taken. This is configured to illustrate conditional branch training behavior.

    The program runs in machine mode with translation off, so the addresses are physical. The program starts at the reset vector, RESET_VECTOR = 0x8000_0000 (bp_defines_pkg.sv).

    Address      Label  Instruction             Purpose
0x8000_0000         c.addi a0, 1            ; prologue
0x8000_0002         addi   t0, t0, 1        ; prologue
0x8000_0006         c.addi a0, 1            ; prologue
0x8000_0008         c.addi a0, 1            ; prologue

0x8000_000A  otop:  c.addi a0, 1            ; outer body
0x8000_000C         addi   t0, t0, 1        ; outer body

0x8000_0010  itop:  c.addi a0, 1            ; inner body
0x8000_0012         addi   t0, t0, 1        ; inner body
0x8000_0016         c.addi a0, 1            ; inner body
0x8000_0018  I:     bne    x6, x0, itop     ; inner loop branch
0x8000_001C  B:     beq    x0, x0, 0x028    ; always taken

0x8000_0028         c.addi a0, 1            ; filler
0x8000_002A         addi   t0, t0, 1        ; filler
0x8000_002E  J:     jalr   x0, 0(x7)        ; indirect jump, to 0x06E

0x8000_006E         c.addi a0, 1            ; filler
0x8000_0070         addi   t0, t0, 1        ; filler
0x8000_0074  K:     jalr   x1, 0(x28)       ; indirect call, to fn
0x8000_0078         c.addi a0, 1            ; after the return
0x8000_007A  O:     bne    x6, x0, otop     ; outer loop branch

0x8000_007E         c.addi a0, 1            ; epilogue
0x8000_0080         addi   t0, t0, 1        ; epilogue
0x8000_0084         c.addi a0, 1            ; epilogue
0x8000_0086  hold:  jal    x0, hold         ; termination

0x8000_0800  fn:    c.addi a0, 1            ; function body
0x8000_0802         addi   t0, t0, 1        ; function body
0x8000_0806         ret                     ; return to 0x8000_0078

    The indirect jump (J:) is an INDIRECT_NONRET because neither register is a link register, and the indirect call (K:) is an INDIRECT_CALL because rd is x1. The ret in fn is a RETURN.

    With one prediction slot, an FTB entry holds one branch, so the path is predicted as several blocks. The accepted p2 slot groups, by block:

    Block start Reached by Branch Position Block end Groups
    0x8000_000A the outer loop branch taken inner loop branch (I:) 7 0x8000_002A 13
    0x8000_0010 itop inner loop branch (I:) 4 0x8000_0030 before the split 26
    0x8000_0010 itop inner loop branch (I:) 4 0x8000_001C after the split 65
    0x8000_001C the inner loop branch not taken always-taken beq (B:) 0 0x8000_003C 14
    0x8000_0028 the beq taken indirect jump (J:) 3 0x8000_0032 13
    0x8000_006E the indirect jump indirect call (K:) 3 0x8000_0078 13
    0x8000_0800 the indirect call ret 4 0x8000_080C 13
    0x8000_0078 the return outer loop branch (O:) 1 0x8000_0098 13

    The c.addi and addi instructions do no useful work. Their purpose is to mix 16-bit and 32-bit instructions and to separate the branches.

    The directions and targets are chosen by the program writer and resolved by the modeled backend, and the register operands play no part in them. x7 and x28 are never read.

    4. Walkthrough¶

    The walkthrough follows branch resolutions from the backend model to the predictor updates.

    Section 4.1 describes update generation and qualification by branch type. Section 4.2 shows the FTB update/FTQ stall conditions. Section 4.3 describes the one resolution in the run that does not train the loop predictor, TAGE and SC, and the FTB entry split that accompanies it.

    Cycle numbers below are events in section 5; each event is a marker in the waveform. A signal the testbench drives, such as tb.bkend_ftq_rsv_val, changes one time unit after the clock edge, as does logic combinational from it, so the waveform first shows the new value at the marker of the next cycle.

    The waveform group bp_cluster_update contains the update valids after the bp_cluster qualification, ftb_update the FTB update, and bp_cluster_p0 the p0 request and its stall.

    4.1 Predictor update generation and branch type qualification¶

    Module ftq_upd_conv generates the update inputs for the predictors, with the exceptions of FTB and RAS. A slot's update valids are asserted only when every predictor that the slot trains can accept the update.1

    bp_cluster decodes the branch type of each update from its uBTB update input and qualifies the per-predictor valids as follows:2

    Predictor        Trained on
uBTB             all branch types except NO_BRANCH
loop predictor   COND
TAGE, SC         COND; each also qualified by its queue ready, SC by sc_enable
ITTAGE           INDIRECT_NONRET, INDIRECT_CALL
FTB              conditional or jump, on the dedicated ftb_upd_* channel
RAS commit       DIRECT_CALL, INDIRECT_CALL, RETURN, RETURN_CALL

    The first resolution is that of the inner loop branch (I:), at position 12 of the block at 0x8000_0000, at cyc 21 (event 1). This COND resolution produces the first uBTB, FTB, loop predictor, TAGE and SC updates. The indirect jump (J:) produces the first ITTAGE update at cyc 66 (event 3). The indirect call (K:) produces the first RAS commit at cyc 78 (event 4), one cycle after its resolution at cyc 77. The first RETURN commit follows at cyc 98 (event 5).

    At cyc 21 (event 1), tb.bkend_ftq_rsv_val is asserted. u_bpu.w_ubtb_upd_u0.[0].valid is asserted with .pc 0x8000_0000 and .pos 12. u_ftq.u_upd_conv.lp_upd_p0.[0].pc is 0x8000_0018, the address of the inner loop branch (I:). u_bpu.w_lp_upd_val_p0, u_bpu.w_tage_upd_val_u0 and u_bpu.w_sc_upd_val_u0 are asserted. ftb_upd_valid_u0 is asserted with ftb_upd_pc_u0 0x8000_0000, ftb_upd_pos_u0 12, ftb_upd_is_br_u0 1 and ftb_upd_hit_u0 0.

    At cyc 66 (event 3), u_bpu.w_ittage_upd_val_u0 is asserted and lp_upd_p0.[0].pc is 0x8000_002E, the address of the indirect jump (J:). ftb_upd_is_jmp_u0 is 1.

    At cyc 78 (event 4), u_bpu.w_ras_commit_val is asserted with ras_commit_br_type INDIRECT_CALL and ras_commit_ret_addr 0x8000_0078.

    At cyc 98 (event 5), u_bpu.w_ras_commit_val is asserted with ras_commit_br_type RETURN.

    The run contains 15 backend redirects:

    4.2 p0 request stall for FTB updates¶

    The FTB has a single read port. When ftq_ftb_sched will issue an FTB update in the next cycle, a p0 request in the current cycle would reach its FTB read at p1 in that cycle, so ftq_npc stalls the request.3 Each FTB update stalls the p0 request for one cycle, 154 cycles in the run. The first stall is for the FTB update at cyc 21 (event 1).

    At cyc 21 (event 1), u_ftq.u_npc.h3_ftb_upd and u_ftq.u_npc.w_hold are asserted, and ftq_pred_val_p0 is deasserted with ftq_pred_pc_p0 0x8000_0010. These signals transition one time unit after the marker of cyc 20. One time unit after the marker of cyc 21, the stall ends and ftq_pred_val_p0 asserts with the same PC. ftb_upd_valid_u0 remains asserted until the marker of cyc 22. The stall therefore occupies the clock cycle preceding the FTB update.

    FTB updates can occur in consecutive cycles, each with its own stall. The first such sequence is four updates of the inner loop branch (I:), from cyc 42 (event 2) to cyc 45. u_ftq.u_npc.h3_ftb_upd remains asserted and ftq_pred_val_p0 remains deasserted from one time unit after the marker of cyc 41 until one time unit after the marker of cyc 45, so no prediction request is presented in those four cycles.

    4.3 Suppressed training for a resolution placed in an occupied slot¶

    In pass 2, the block at 0x8000_0010 contains both the inner loop branch (I:) at position 4 and the always-taken beq (B:) at position 6, and the FTB entry's single slot holds the inner loop branch. The backend redirects to 0x8000_0028 at cyc 166 (event 6), and the beq resolves at cyc 168 (event 7). The FTQ places the resolution in the occupied slot, whose prediction metadata describes the inner loop branch, and suppresses the loop predictor, TAGE and SC updates.4 The uBTB and FTB updates are still generated, and the FTB update splits the entry so that the block thereafter ends at 0x8000_001C. The FTQ accepts the first p2 group with the new block end at cyc 176 (event 8). This is the only such placement in the run, so the loop predictor, TAGE and SC counts are 111, not 112.

    The figure below shows the block before and after the split.

    At cyc 166 (event 6), tb.bkend_ftq_redir_val is asserted with tb.bkend_ftq_redir_pc 0x8000_0028, tb.bkend_ftq_redir_pos 6 and tb.bkend_ftq_redir_taken 1.

    At cyc 168 (event 7), u_ftq.u_resolve.rsv_plc_occ is asserted. u_bpu.w_ubtb_upd_u0.[0].valid is asserted with .pc 0x8000_0010 and .pos 6, and lp_upd_p0.[0].pc is 0x8000_001C. w_lp_upd_val_p0, w_tage_upd_val_u0 and w_sc_upd_val_u0 are deasserted. ftb_upd_valid_u0 is asserted with ftb_upd_pos_u0 6, ftb_upd_hit_u0 1, u_bpu.u_ftb.u_ftb_cntrl.upd_split 1 and u_bpu.u_ftb.u_ftb_cntrl.upd_cut_pos 6.

    At cyc 176 (event 8), u_ftq.w_ok_slot_p2 is asserted with u_bpu.r_pc_p2 0x8000_0010 and bpu_blk_pft_p2 0x8000_001C. bpu_slot_p2.[0].pos is 4.
