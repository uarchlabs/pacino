### Two defects, both inert rather than wrong

1. A COUNTED CHECK THAT COULD NOT FAIL. tb_bp_cluster D2 tested
   !$isunknown of three queue-status bits. Under the two-state value
   model this simulator uses, $isunknown is constant 0, so the
   condition could never be false. It was counted among the 973.
   This is the identical defect BP-094 removed from A3.

   All 450 chk/chk_q/chk_eq/chk_eq_q sites in the file were
   enumerated and classified; this was the only surviving instance,
   and no $isunknown appears in any other bpu testbench. The class
   is bounded at one. Replaced with the specific value each bit must
   hold, sampled every cycle rather than once -- which is what the
   comment above it already claimed. Count held at 973 by design, so
   the group subtotals stay comparable. Proven to fail when mutated:
   972/1, exit 2.

2. TD#111 WAS CLOSED TOO EARLY, AND ONE WATCHDOG COULD NOT FIRE.
   The TD named four testbenches and BP-096 fixed those four. BP-097
   swept all 18 and found three with no watchdog at all (tb_tage,
   tb_loop_pred, tb_bp_history) and one, tb_bp_cluster, whose
   watchdog waited on repeat (200000) @(posedge clk).

   A cycle-based watchdog waits on the very clock a hang stops.
   Measured, not argued: clock frozen, run hung indefinitely, make
   never returned. All four repaired time-based, each proven in both
   directions by a frozen-clock probe. tb_bp_pkg needs none -- no
   clock, no blocking construct, cannot hang.

   RULE, now in Open Items row 12: a watchdog is a TIME delay, never
   a cycle count.

## Decisions (session-066)

### Planning documents are IA-read-only

Stated above. Belongs in CLAUDE.md as a fixed constant, in the same
register as "no VHDL," with a clause making it override a task
file's Deliverables section -- otherwise the next prompt can undo it
the same way BP-097 did.

Suggested wording:

  Planning documents are never modified by the IA. Files under
  planning/, pa_handoffs/ and docs/ are read-only in every task. The
  IA reports what a planning document should say; the PA drafts it
  and Jeff applies it. This is not overridable by a task file's
  Deliverables section.

Jeff's call whether to adopt it and in what form.

### Historical records are not corrected

Constraint 8 of BP-097 held and should be kept as a standing rule.
docs/sessions.json, prior Results Capture sections, and closure
entries in CLOSED_TECH_DEBT.md record what was true when written. A
stale type name or figure in one of those is not a defect.

This is why BP-095.md and INFRA-010.md still name the deleted
ittage_assert_bind.sv and were left alone. BP-096.md was different
only because its own task was ordered to delete that file, so the
entry was wrong when written; that one line was removed.

### The validator's scope, not the prompt files

60 of 184 prompt files carry manifest paths that no longer resolve:
two from the BP-096 deletion, 58 from the pre-bpu directory layout
or annotated "does not exist yet." This does not matter today --
validation is a pre-run gate on the single file being extracted, and
completed task files are never re-validated.

It matters only if TD#99's CI ever runs the validator across
prompts/. Recorded as a one-line scope note in TD#99. Do not open a
cleanup task for the 58.

### Watchdog magnitude left non-uniform

tb_ittage_table's #100000 stays, with the reason recorded. BP-096's
four watchdogs sit at 4.3x-6.1x of measured completion; the ten
older ones sit at 20x-439x. Retuning one file to the tighter shape
would align it with four and misalign it with nine, no rule document
specifies a ratio, and a late watchdog still converts a hang into a
failure. Proven to fire regardless.

The headroom-for-a-slower-config argument was tested and does NOT
apply here: tb_ittage_table completes at 266 units with and without
+ITTAGE_FAST_INIT, because sim_ittage_table compiles ittage_table.sv
without the sram_init.sv the strap acts on. That plusarg is inert
for this target. Open Items 16.

CAUTION on the ratio table: the completion figures behind it are
round to a degree that suggests coarse granularity (68000, 15000,
13000, 8000), and at least one entry is strap-dependent. BP-096
measured tb_tage_manual at 1175, BP-097 at 1000. Re-measure before
anyone writes a ratio rule.

### A comment may not begin with the word Verilator

v5.048 parses "// Verilator ..." as a lint pragma and fails with
%Error-BADVLTPRAGMA. Hit twice while writing comments this session.
This is a real v5.048 workaround and belongs in CLAUDE.md with the
others.
