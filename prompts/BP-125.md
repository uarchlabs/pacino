DCD-35, with an oracle sweep of 458752 encodings against spike-dasm,

Jeff ruled on:

  successor becomes the fall-through. IFU-18 and ftq_ifu_interfaces.md

  VMEM default and sumop 10000 are reported, not changed. BP-124's
  sweep found 24742 that decode accepts. Their behaviour is
  UNSPECIFIED; RVA23 strongly recommends illegal-instruction.

## Decisions made not explicit in the prompt
None was put to Jeff in session (automated mode). Each is the IA's
recommended option, built and provisional.

- D1 (provisional). The L1I-24 replacement update for a cacheable
  request merged onto an uncached MSHR is made at the install. The
  install from such a register moves the way, through a new fp port on
  l1i_meta_array (a second writer of the replacement state beside the
  compare stage). When both name one set in one cycle, the install's
  way is applied on top of the compare stage's value. The alternative,
  a lookup for the merged request, would read the array for a line
  already in flight. A cacheable register's install does not update
  again (C5).
- D2 (provisional). The per-class count puts each VRSV encoding under
  the class of the form its normalized word decodes to. The mew class
  takes the forms with no class of their own. DCD-32's classes overlap
  on mew.
- D3 (provisional). The decoder marks a reserved memory form VMEM and a
  reserved OP-V form VOTHER, so dec_vec's existing illegal path and
  DCD-36 zeroing apply unchanged. No new v_op_class value.
- D4 (provisional). T73d and T73e, which forced the IFU bits to show
  decode ignored them, keep their hazard checks without the forcing.

- D5 (provisional). The rewritten conditional slot is still killed
