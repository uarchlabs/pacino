One end-state task in five parts: the two rulings Jeff made after
BP-124, and three open items he added to it. Each is written in the
planning documents named in Context Loaded, and every choice the PA
can foresee is made there or below. One that turns up anyway is
handled as session-075 ruling item 4 says (Binding Previous
Decisions).

   the FTQ keeps the entry's taken and corrects only the target
   (ftq_ifu_interfaces.md 7 W1, TD#174).

   (dcd_decisions.md DCD-32, TD#175): the 24742 encodings BP-124's

   ibuf: decode computes its own and nothing reads them (TD#148).

E. Three FTQ items carried since BP-117: a check pinning the entry
   after an M1 JAL ahead of a predicted-taken slot; a measured p2 and
   p3 post-redirect latency; and the // OLD: comment lines left in
   ftq.sv.

## Hypothesis
Every part can be built or checked so that each rule it names has a

## Background
BP-124 built the decode representation and legality of DCD-21 to
DCD-35, with an oracle sweep of 458752 encodings against spike-dasm,
and passed tools/regress.sh with 153 targets. It reported two things
Jeff ruled on:

- ftq_ifu.sv's predecode_correct writes taken = 0 for a conditional
  at the predicted-taken slot under M3 (a wrong target), so the
  successor becomes the fall-through. IFU-18 and ftq_ifu_interfaces.md
  6 say predecode cannot know a conditional's direction and the
  entry's prediction stands. The backend corrects the result, so the
  cost is performance, not correctness.
- DCD-32 then said reserved vector encodings other than VOTHER, the
  VMEM default and sumop 10000 are reported, not changed. BP-124's
  sweep found 24742 that decode accepts. Their behaviour is
  UNSPECIFIED; RVA23 strongly recommends illegal-instruction.

## Binding Previous Decisions
- Everything else in W1 stands: slot_valid and br_type from the
  predecode info, the target from ifu_ftq_target, pred_src
  PRED_NONE, placement and the killing of later slots, and W2. A
  non-conditional at mis_pos is unchanged.
- W3U stands as BP-124 reported it; under ifu_ftq_uc_end a
  conditional at mis_pos was not predicted taken.
- An illegal packet carries ALU_ILL and nothing else, with a zero
  vector packet (DCD-36).
- A slot carrying a fetch fault is not decoded as illegal (DCD-19).
- The oracle file and spike-dasm's text in it do not change; what

- is_vsetvl and needs_vtype stay in vec_decode_pkt_t, which decode
  fills (DCD-17, CLAUDE.md); only ifu_pd_pkt_t loses them.
- ftq.sv stays purely structural (ftq_decisions.md 7); removing its
  // OLD: lines changes no logic.
- tools/known_failures.txt is not edited (CLAUDE.md).
- A design choice not settled by this task or the planning set is

  provisional, and continues; Jeff confirms or reverses after

## Specific Requirements
This task is written as PROBLEMS. Each states what must be true at the
end. Method, order and decomposition are the IA's; WHAT is built is
not, and is fixed below and in the planning documents.

FIX WHAT YOU FIND. A defect is behaviour that contradicts the planning
set or the ratified specification. One found while working any
problem is repaired in this run so that it matches them, with a check
that fails before the fix. When more than one repair would match, the
choice between them is a design choice, handled as Binding Previous
Decisions says. A negative result -- a rule examined and found
already met, with the evidence -- is a completed item.

Problem 0. The starting tree.
  Before any edit: run tools/regress.sh and record its summary, and
  record cycles, retired instructions and mispredicts after warm-up
  for every tb_fe_top program. These are the baselines for Problem 6.

Problem 1. W1 for a conditional (Part A, TD#174).
  Done when:
  - when a writeback's mis_pos is the predicted-taken position and the
    instruction there is a conditional branch (M3), W1 writes the slot
    with taken set, as the entry predicted, and with the target from
    ifu_ftq_target; the successor W3 derives is that target;
  - every other case W1 handles writes what it wrote before;
  - tb_ftq_ifu checks the M3 conditional case (taken kept, target
    corrected, the successor the corrected target) and one
    non-conditional M3 case unchanged, and the first check fails on
    the starting tree;
  - Results Capture reports, for every tb_fe_top program, how many M3
    writebacks named a conditional, and each change in cycles or
    mispredicts against the Problem 0 baseline is explained by them.

Problem 2. Reserved vector encodings illegal (Part B, TD#175).
  Done when:
  - instr_decoder raises illegal-instruction, with the DCD-36 packet,
    on every encoding in each class DCD-32 lists;
  - dec_sweep_expect.py expects illegal for every encoding its rule
    VRSV covered, and rule VRSV no longer classes any encoding as
    legal; sim_dec_sweep passes over all 458752 encodings with
    decode matching the expectation on each;
  - Results Capture gives, per DCD-32 class, the count of encodings
    that became illegal, and the total equals the 24742 BP-124
    reported, or each difference is explained;
  - tb_instr_decoder checks at least one encoding of each DCD-32 class
    and, for each class, the nearest legal encoding (the same
    instruction with the field at its defined value) still decoding
    as before. Each word is produced as BP-124 produced T77's: clang -c
    (or its .insn directive for a reserved form) and spike-dasm, and
    asm_dec_words covers the new words;
  - every tb_fe_top program still retires; a program that used one of
    these encodings is a defect in that program, fixed with the
    instruction at its defined value.

Problem 3. The same-cycle cacheable merge (Part C, TD#172).
  Done when tb_l1i has a directed test in which a cacheable request
  merges onto an MSHR taken by an uncached request in the same cycle
  that MSHR's fill lands, and checks that the fill is installed and
  the replacement state updated, as L1I-24 requires of any cacheable
  request merged onto that MSHR; the test fails when the second term
  of fil_alloc (the cacheable merge in the fill's own cycle) is
  reverted.

Problem 4. is_vsetvl and needs_vtype leave ifu_pd_pkt_t (Part D,
TD#148).
  Done when:
  - ifu_pd_pkt_t in bp_structs_pkg no longer declares them;
  - ifu_predecode no longer drives them, and the ibuf no longer
    stores or passes them;
  - every reader of ifu_pd_pkt_t under rtl/ is updated, tb_ibuf,
    tb_ifu, tb_instr_decoder and tb_fe_top included, and nothing
    else in the struct changes;
  - Results Capture gives ifu_pd_pkt_t's width before and after.

Problem 5. The FTQ carry-overs (Part E).
  Done when:
  - tb_ftq_ifu checks the entry after an M1 writeback whose JAL lies
    before the predicted-taken position: the JAL's slot written as
    W1 states, every later slot killed, and the successor the JAL's
    target; the check fails when that W1 placement is reverted;
  - tb_ftq drives a p2 and a p3 redirect, and Results Capture reports
    the cycles from the redirect to the first translation request
    for the flush index F, against ftq_decisions.md 5.1's inferred
    1 cycle; a check pins the measured value;
  - ftq.sv has no // OLD: lines, and its lint and every ftq target
    pass as before.

Problem 6. The end state.
  Done when:
  - every rule named in Problems 1 to 5 is built or checked with a check that
    fails when that rule's logic is reverted, shown by reverting it on
    a copy in the scratch directory;
  - every tb_fe_top program retires exactly, with cycles, retired
    instructions and mispredicts equal to the Problem 0 baseline, or
    each change is explained;
  - no known correctness defect is open;
  - tools/regress.sh passes.

Package changes, all of them:
  - bp_structs_pkg.sv: is_vsetvl and needs_vtype removed from
    ifu_pd_pkt_t (Problem 4), and comments made untrue by that
    corrected.
A further package change found necessary is a design choice,
handled as Binding Previous Decisions says, and listed with its
reason.

Choices already made, which the IA does not revisit: which encodings
are illegal (DCD-32's classes); what W1 writes for a conditional
under M3; that the oracle file does not change; which two fields
leave ifu_pd_pkt_t.

  writes. Every limit in these Constraints binds every command a
  script, Makefile recipe or tool the IA writes or runs executes:
  none runs git, reaches the network or installs anything.
- DELETION: a command deletes or moves only files this run created
  (build outputs included) and files in the scratch directory.
  Existing files are changed in place, as WRITE allows, and never
  deleted or moved. tools/regress.sh and make may write their own
  temporary and build directories as they do today.
- SCRATCH: one directory the IA creates outside the repository, for
  the reversion copies and logs. It is removed at the end, after its
  contents are summarised in Results Capture.
- GIT: the IA runs no git command. It may run tools/regress.sh, which
  makes git calls of its own; that grant is to run the script, not to
  run any command the script contains. Reading regress.sh to see what
  it calls grants nothing either. "No git command" includes read-only
  ones such as git status, git diff and git log.

Not granted: any change under rtl/mmu/, tools/, planning/,
pa_handoffs/ or docs/; any package change except those listed or as
Binding Previous Decisions allows; any change to
tools/known_failures.txt; any change outside the repository except in
the scratch directory and the temporary directories tools/regress.sh
and make create.

No process the task starts is left running when it ends. A wait for a
