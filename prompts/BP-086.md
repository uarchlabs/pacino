# Task Overview

Rewrite ubtb.sv to the single-lookup block descriptor model, and
rewrite tb_ubtb.sv to match.

Today ubtb.sv performs two independent lookups per cycle: slot 0 at
pred_pc_p0 and slot 1 at pred_pc_p0 + 32. That is the retired
two-PC-range model. One uBTB lookup must return one entry describing
one block, with the two prediction slots being the two conditional
branch fields of that entry.

The entry format has already been reshaped in bp_structs_pkg.sv and
bp_defines_pkg.sv to mirror the FTB entry. This task brings the RTL
and the testbench to those types.

Expect bp_cluster.sv to stop elaborating when this lands. That is a
known and accepted consequence; see the Constraints.

## Background

The uBTB is the first predictor in the cluster. It produces a
prediction at p1 from a combinational read of its registered array.

The entry format has been reshaped to mirror the FTB entry
(ftb_decisions.md section 4). One entry now describes one
UBTB_BLOCK_BYTES block and holds two conditional branch fields
(br0, br1), one jump field, and a partial fall-through address with
a carry bit. The types are ubtb_cond_t, ubtb_jmp_t, ubtb_entry_t,
ubtb_pred_t, ubtb_blk_t and ubtb_upd_t in bp_structs_pkg.sv.

ftb_cntrl.sv is in the context because it already implements the
same target encoding, target reconstruction, fall-through reduction
and reconstruction, and bimodal counter step against the identical
field widths. Its helper functions are the reference for the
equivalent uBTB logic. The uBTB is a different structure with a
different tag width and a simpler replacement policy; do not copy
its pipeline, its storage split, or its read-port arbitration.

planning/interfaces/ubtb_interfaces.md is the interface authority.

## Binding Previous Decisions

- One lookup per cycle. One index and one tag derived from
  pred_pc_p0, one way search over UBTB_WAYS. The matched entry
  supplies every prediction slot. There is no second lookup, no
  slot-1 PC, and no pred_pc_p0 + 32 anywhere in the module.
- Slot 0 is built from the matched entry br0 field. Slot 1 from br1.
- The jump field is the block-terminating control instruction. It is
  reported in the lowest prediction slot that carries no valid
  conditional field.
- NUM_PRED_SLOTS sizes the prediction and update port arrays. It
  does not change the number of lookups. At NUM_PRED_SLOTS = 1 only
  the br0 field is reported.
- Targets are stored as displacements from block start with a
  fit/overflow/underflow status, and reconstructed to full width on
  read. The reconstruction is used unconditionally; there is no
  fall-through error check and no error output.
- conf is a bimodal direction counter. Its most significant bit is
  the predicted direction for that conditional branch.
- The replacement policy stays as it is today: a per-set round-robin
  write pointer. Do not introduce tree-PLRU.
- The storage stays a single array inside ubtb.sv. Do not split it
  into separate data and valid modules the way the FTB is split.
- bp_structs_pkg.sv and bp_defines_pkg.sv are already correct. Do
  not change them.
- BUG-006: build from the tree. If a Context Loaded path does not
  exist, STOP and report it.

## Specific Requirements

1. Read ubtb.sv, tb_ubtb.sv, and the uBTB type definitions in
   bp_structs_pkg.sv before editing anything.

2. Rewrite the ubtb.sv prediction path.

   Derive one set index and one tag from pred_pc_p0. Search all
   UBTB_WAYS for a valid entry whose tag matches. Delete the
   per-slot slot_pc computation and the generate loop that
   replicates the lookup.

   Drive the new blk_p1 output: hit is the way-match result;
   pft_addr is the entry fall-through reconstructed to full width
   from the stored partial value and the carry bit.

   Build each pred_p1 slot from the matched entry. For a slot
   carrying a conditional field: valid from the field valid,
   br_type COND, br_taken from the conf most significant bit,
   target reconstructed from the stored displacement, and pos and
   conf from the stored fields. For the slot carrying the jump
   field: br_type from the stored is_call, is_ret and is_jalr bits
   decoded to bp_br_type_e, target reconstructed from the stored
   jump displacement.

   Drive carry in each slot from the stored entry carry bit.

   On a miss every pred_p1 slot is driven to zero and blk_p1.hit is
   zero.

3. Rewrite the ubtb.sv update path.

   Each update channel derives its own set index and tag from
   upd_u0[u].pc. Both channels may target the same entry in the same
   cycle and write different fields of it.

   On a tag hit where the addressed field is already occupied: step
   the conf counter toward the resolved direction, incrementing on
   taken and decrementing on not-taken, saturating at both ends.
   Rewrite the stored target if the resolved target differs. Leave
   the stored position unchanged.

   On a tag hit where the addressed field is empty, and on a tag
   miss that allocates a new entry: write the field fresh. Set conf
   to UBTB_CONF_INIT_TKN when the branch resolved taken and to
   UBTB_CONF_INIT_NTK when it resolved not-taken. Write the
   position from upd_u0[u].pos.

   Write the jump field whenever upd_u0[u].is_jmp is set. The jump
   target is rewritten on every such resolve. The jump position
   follows the same fill rule as the conditional positions.

   Reduce upd_u0[u].pft_addr to the stored partial fall-through and
   carry on every update.

   Keep the existing round-robin write pointer for miss allocation.

4. Rewrite tb_ubtb.sv for the new entry format and the single

   - both update channels writing different fields of one entry in

- Index and tag now derive at block granularity, matching the

  UBTB_IDX_BITS], tag = the UBTB_TAG_BITS bits directly above it.
  get_base added for the block start that every displacement is
  relative to.
- Prediction is one always_comb: one index, one tag, one way search
  over UBTB_WAYS, one matched entry. The generate block, the
  per-slot slot_pc, and the pred_pc_p0 + 32 lookahead are deleted.
- blk_p1.hit is the way-match result. blk_p1.pft_addr is the stored
  partial fall-through plus carry reconstructed to full width,
  unconditionally, with no error check and no error output.
- Slot build: slot 0 from br0, slot 1 from br1. A slot carrying a
  conditional reports valid, COND, br_taken from the conf MSB, the
  reconstructed target, and the stored pos and conf. The jump field
  is reported in the lowest slot with no valid conditional field,
  with br_type decoded from is_call / is_ret / is_jalr. carry in each
  reported slot comes from the stored entry carry bit. On a miss
  every slot and blk_p1 are driven to zero.
- Helper functions ported from ftb_cntrl against the UBTB widths:
  recon_br, recon_jmp, enc_br_disp, enc_jmp_disp, br_stat, jmp_stat,
  conf_step. New: recon_pft, jmp_br_type, get_base.
- Update path rewritten. Each channel derives its own index, tag and
  base from its own pc and does its own way search against the
  registered array. A new pure function apply_upd applies one
  resolved channel to an entry, so the single-channel case and the
  two-channels-on-one-entry case share one body. Occupied field ->
  conf steps toward the resolved direction with saturation, position
  held, target re-encoded. Free field or miss-allocate -> filled
  fresh with UBTB_CONF_INIT_TKN / UBTB_CONF_INIT_NTK and the update's
  position. Jump field written whenever is_jmp is set, target
  rewritten every time, position on the same fill rule. Fall-through
  reduced to pft plus carry on every update. Round-robin write
  pointer kept for miss allocation.
- Storage stays one array in the module; no split into data and
  valid peers, no tree-PLRU.
- An initial-block invariant check on the two conf init constants,
  mirroring the equivalent check in ftb_cntrl.

tb_ubtb.sv, rewritten: 15 test cases, 259 self-checking assertions,
tb_ras-style scoreboard with pass and fail counters, $fatal(1) on any
failure so a failing run returns a non-zero exit code, and a
watchdog. Covers every item in Specific Requirement 4 plus the
carried-forward checks from the old suite.

## Assumptions made not explicit in the prompt

- Index and tag placement. The index and tag comments in
  bp_defines_pkg.sv and bp_structs_pkg.sv still say PC[26:7], which
  describes the retired instruction-granularity indexing. The task
  binds those packages as correct and forbids changing them, and
  names ubtb_interfaces.md as the interface authority. The interface
  specifies index = pred_pc_p0[UBTB_IDX_BITS+UBTB_OFFSET_BITS-1 :
  UBTB_OFFSET_BITS] and tag = the upper VA bits above the index, so
  the RTL indexes at block granularity: index = pc[10:5], tag =
  pc[30:11]. The stale PC[26:7] comments are left untouched as
  out-of-scope; they should be corrected in whichever task next
  touches those packages.
- pred_p1[s].carry. Requirement 2 says to drive carry in each slot
  from the stored entry carry bit, which is the fall-through carry.
  The ubtb_pred_t comment in bp_structs_pkg.sv instead describes
  carry as "target lies outside this block". The requirement is
  followed. For a slot whose valid bit is 0 the whole slot is zeroed,
  per the interface rule that all other fields are driven 0 when
  valid is 0; carry is therefore driven from the entry bit only for
  reported slots.
- blk_p1 on a miss. Requirement 2 states only that blk_p1.hit is 0
  and every pred_p1 slot is zero. blk_p1.pft_addr is defined as
  meaningful only when hit is 1, so the whole struct is zeroed on a
  miss for determinism rather than reconstructing from an unmatched
  way. This is checked in TC01.
- An update with valid=1 but is_br=0 and is_jmp=0 is treated as a
  legal boundary-only resolve: it allocates or refreshes the entry
  and writes pft and carry without touching any field. This is what
  produces the "hit with no field occupied" state the interface
  calls a legal state, and it is the stimulus for TC04.
- NUM_PRED_SLOTS above 2 is undefined per the interface. The RTL
  reports no conditional field for slots above 1, so a jump could
  land in slot 2. No behaviour is claimed for that configuration and
  it is not tested.

## Decisions made not explicit in the prompt

- Dual-channel merge. The two channels are merged combinationally
  rather than issued as two independent writes. Each channel builds
  its write-back entry by replaying the field writes of any earlier
  channel that targets the same set, way and tag, and only the last
  channel targeting a given (set, way) drives the array. Two
  independent whole-entry writes would have let the later channel's
  fresh-allocate zeroing clobber the earlier channel's field, which
  would break the required "both channels write different fields of
  one entry in the same cycle" case. TC11a checks this both for
  field content and for the write pointer stepping once.
- apply_upd is a pure function taking the entry to modify and
  returning the result. The first implementation chained through an
  array of per-channel results and tripped Verilator ALWCOMBORDER
  ("always_comb variable driven after use"), because the array was
  read for an earlier index before being written for the current
  one. Restructuring to a pure function removed the ordering hazard
  without a lint waiver.
- Way conflict between channels. If two active channels land on the
  same set and way with different tags, the later channel wins
  outright and the earlier channel's update is dropped. This is a
  degenerate case the interface already treats as a producer
  scheduling concern (UI3); it is documented in the RTL comment and
  is not tested.
- No generate blocks are used anywhere in the rewritten ubtb.sv. The
  old generate loop over prediction slots was the vehicle for the
  retired two-lookup model; the replacement is a single always_comb
  with a procedural loop. The Constraints ask for generate block
  style to be described explicitly, which is vacuous here because
  none remain.
- The target is re-encoded on every conditional resolve rather than
  compared first. An unchanged target stores the same value, so
  "rewrite the stored target if the resolved target differs" is
  satisfied without a comparator. This matches ftb_cntrl.
- Testbench exit convention follows tb_ras: pass and fail counters
  and $fatal(1) on failure. The old tb_ubtb used $finish(1), which
  Verilator does not turn into a non-zero exit code, so a failing
  run would previously have reported a passing make target.

## RVA23 compliance risks and gaps noticed

None introduced by this task. Two standing observations:

- The uBTB tag is 20 bits against 29 available above the index, so
  two PCs can alias to one entry and a hit can be the wrong entry.
  This is an accuracy property, not a correctness one, because the
  FTB result at p2 is authoritative and the cluster is required to
  compare and redirect on disagreement. It is worth noting that the
  fall-through reconstruction has no error check (ftb_decisions.md
  4.5 removed it), and 4.5 justifies that removal by the FTB's full
  26-bit tag. That justification does not transfer to the uBTB. An
  aliased uBTB hit can therefore return a fall-through belonging to
  a different block. The p2 FTB comparison still catches it, so this
  is a wasted-cycle issue rather than an architectural one, but it
  is a real difference from the structure the reconstruction rule
  was written for.
- The 8-wide front-end goal is unaffected: one lookup now describes
  one 32-byte block of 8 expanded instructions, which is the shape
  the FTB and the cluster already assume.
