## Background

The uBTB now performs one lookup per cycle. One entry describes one
block. The two prediction slots are the two conditional branch
fields of that entry, and the block-terminating jump is reported in
the lowest slot carrying no valid conditional field.

Three things changed at the uBTB interface. ubtb_pred_t gained pos
and conf, and its carry field is now the entry fall-through carry
rather than a property of the slot target. A new output blk_p1 of
type ubtb_blk_t carries the entry hit and the reconstructed
fall-through; hit is now reported once per lookup rather than per
slot. ubtb_upd_t was reshaped to mirror the FTB update port: it no
longer carries br_type or carry, and now carries is_br, br_idx, pos,
is_jmp, jmp_target, is_call, is_ret, is_jalr and pft_addr.

BP-086 recorded the failing references: a missing blk_p1 pin on the
instance, and reads of ubtb_upd_t.br_type and ubtb_upd_t.carry in
the update fan-out. Verify them against the file.

Separately, the package gained two things for the metadata path.
ftb_pred_meta_t is new and holds the FTB hit, way and jump position;
bp_ftq_meta_t gained an ftb member of that type. bp_ftq_slot_t
gained a pos field for the in-block branch position.

ftq_bpu_interfaces.md section 7 specifies the metadata write groups.
Section 4 specifies the p1 prediction. Both are authority.

## Binding Previous Decisions

- ubtb.sv, bp_structs_pkg.sv and bp_defines_pkg.sv are correct as
  they stand. Do not change them.
- The uBTB reports hit once per lookup on blk_p1.hit. A pred_p1 slot
  with valid = 0 on a hit means that slot carries no branch, which
  is a legal state; the successor is then the fall-through.
- The p1 selection mux rule is unchanged: loop_pred when
  lp_pred_is_loop is set, else uBTB when the slot is valid, else the
  slot carries no prediction. Slot 1 has no loop_pred producer and
  takes the uBTB prediction (TD#105).
- The metadata finalizes at two stages. The p2 group writes the
  tage, ittage, lp and ftb members of bp_ftq_meta_t; the p3 group
  writes the sc member. The two sets are disjoint so the FTQ never
  merges.
- The loop predictor finalizes at p1. Its result is registered and
  presented in the p2 group so the FTQ performs one slow-path write
  per entry.
- bp_ftq_meta_t is carried per slot. The array is declared at the
  port, not inside the struct.
- The FTB hit, way and jump position are scalar within the entry:
  the FTB indexes one entry per lookup and both slots come from it.
  The cluster writes the same values into every slot's copy.
- BUG-006: build from the tree. If a Context Loaded path does not
  exist, STOP and report it.

   selection mux, which reads the registered loop_pred result, so
   splitting them across the boundary would compare a p0-cycle hit
   against a p1-cycle slot. r_ubtb_blk_p1 sits beside
   r_ubtb_pred_p1 in the same p0 -> p1 group.

2. The loop metadata is registered p1 -> p2 in the cluster's own
   stage register group, r_lp_pred_p2 <= w_lp_pred_p0, alongside the
   existing p1 -> p2 transfers. The prompt says the loop result is
   "registered and presented in the p2 group" without naming the
   register.

3. Higher slots of bpu_meta_lp_p2 report no loop state rather than a
   copy of slot 0. See Decisions.

4. The FTB metadata is driven unconditionally, not gated on
   bpu_meta_val_p2. The group's valid names the write; the payload
   is a don't-care when the valid is low. This matches how the p1
   and redirect output arrays are driven.

## Decisions made not explicit in the prompt

1. Update classification source. Detailed in Other Notes. Chosen:
   structural decode from the reshaped struct's own is_br / is_jmp /
   is_call / is_ret / is_jalr bits.

2. w_upd_type_u0 stays a bp_br_type_e. The three consumers --
   w_upd_any_u0, w_upd_cond_u0, w_upd_ind_u0 -- are unchanged in
   both expression and meaning, so the fan-out to TAGE, ITTAGE, SC
   and loop_pred is bit-identical to BP-085 for any input that
   BP-085 could also have seen. Only the producer of the enum
   changed. This is the smallest edit that satisfies the Constraints
   line freezing the other predictors' fan-out.

3. bpu_meta_lp_p2 for slots above 0 is driven to
   bp_loop_meta_t'('0), not to a copy of slot 0. loop_pred is single
   slot (TD#105) and its result describes the slot 0 branch. Copying
   it into slot 1 would hand the FTQ loop-table coordinates -- way,
   index, tag, victim -- belonging to a different branch, and the
   resolution path would train the wrong entry. Zero reports
   lp_hit = 0 and lp_pred_is_loop = 0, which the update path reads
   as "no loop state for this slot". The port has a producer, so the
   "every metadata output must have a producer" constraint is met;
   this is a real driver, not a tie-off of a predictor output.

4. The FTB metadata is assembled field by field rather than by
   struct assignment, so the three source nets are visible at the
   assignment and a future width change fails loudly.

5. The lp_pred_t -> bp_loop_meta_t map is an always_comb block, not
   a chain of continuous assigns. It reads r_lp_pred_p2, a flop
   output, so it is nba_sequent and not subject to the CLAUDE.md
   stl_sequent hazard.

6. The existing "section 7: update channel" comment in the port list

   correcting it is outside this task's scope. The new group is

## Other Notes

### Requirement 4 -- what became of blk_p1.pft_addr

It has no consumer. Stated here per requirement 4 and per the
Constraints line "if a signal has no consumer, say so". It is not
tied off and is not read; it is available on w_ubtb_blk_p1 for the
task that adds its consumer.

There is exactly one place in the cluster where a p1 fall-through
would be consumed, and this task cannot use it. That place is the
p1_succ operand of the p2 redirect comparison in p2_succ_comb:

```
  p1_succ = r_slot_p2[s].taken ? r_slot_p2[s].target
                               : w_ftb_pft_addr_p2;
```

The not-taken operand is the FTB p2 fall-through. Per
ubtb_interfaces.md, blk_p1.pft_addr is "authoritative for the
cluster when no slot is taken", so on the merits this operand should
be the registered uBTB fall-through. Three reasons this task does
not make that change:

1. The task Constraints freeze it: "The redirect derivation ... stay
   as BP-085 left them." Changing an operand of the redirect
   comparison is a change to the redirect derivation, and it is a
   behavioural one -- it makes p2 redirects fire on cases that
   currently compare equal.

2. It is incomplete on its own. blk_p1.pft_addr reads 0 on a uBTB
   miss, and a miss is the common case at start-up. Substituted
   directly it would compare 0 against the FTB fall-through and
   assert a redirect on every miss. A correct version needs a
   miss-case default -- the block-aligned next block, r_pc_p1 +
   FTB_BLOCK_BYTES -- which is new logic, not a rewire, and is
   beyond "what the reshaped uBTB interface requires".

3. No p1 output port carries a fall-through to the FTQ.
   ftq_bpu_interfaces.md section 4 lists four p1 outputs --
   bpu_pred_val_p1, bpu_pred_idx_p1, bpu_pred_slot_p1,
   bpu_pred_ras_p1 -- and none of them is a fall-through or a
   successor. So there is no second candidate consumer to fall back
   on, inside the cluster or at its boundary.

Recorded as Deferred Work item 2.

### Requirement 5 -- update classification source

Chosen: a structural decode from the reshaped ubtb_upd_t's own
is_br, is_jmp, is_call, is_ret and is_jalr bits, in the gen_slot
loop:

```
  assign w_upd_type_u0[gs] =
        ubtb_upd_u0[gs].is_br   ? COND
      : !ubtb_upd_u0[gs].is_jmp ? NO_BRANCH
      : ubtb_upd_u0[gs].is_ret  ? RETURN
      : ubtb_upd_u0[gs].is_call ? (ubtb_upd_u0[gs].is_jalr
                                     ? INDIRECT_CALL
                                     : DIRECT_CALL)
      : ubtb_upd_u0[gs].is_jalr ? INDIRECT_NONRET
      :                           DIRECT_UNC;
```

Why this source, against the alternatives:

- It is literally the same source the FTB update fan-out decodes.
  The reshaped ubtb_upd_t was made to mirror the FTB update port,
  and w_ftb_upd_val_u0 is ftb_upd_valid_u0 & (ftb_upd_is_br_u0 |
  ftb_upd_is_jmp_u0) -- the same is_br / is_jmp pair. Both fan-outs
  now read one set of resolved facts, so they cannot diverge, which
  is what requirement 5 asks for.

- The decode logic is the decode already in this file. The trailing
  four arms are the FTB jump classification from p2_class_comb,
  arm for arm, in the same order: is_ret first because a return is
  also a JALR, then is_call split by is_jalr into INDIRECT_CALL and
  DIRECT_CALL, then bare is_jalr as INDIRECT_NONRET, then
  DIRECT_UNC. It is also the same order as ubtb.sv's own
  jmp_br_type function, so predict-side and update-side
  classification agree.

- The precedence -- is_br outranks is_jmp -- is the precedence
  p2_class_comb applies to the FTB result, where a valid conditional
  field owns the slot and the block-terminating jump is placed in
  the lowest slot carrying no conditional. Reproducing it here keeps
  the update classification and the prediction classification the
  same function of the same facts. It matters only for a channel
  asserting is_br and is_jmp together, which is legal against the
  uBTB entry -- the two write different entry fields -- but ambiguous
  for the fan-out, since TAGE trains on conditionals and ITTAGE on
  indirects. Conditional wins, matching p2.

Alternatives rejected:

- ras_commit_br_type. It is the only remaining bp_br_type_e on the
  update side of the port list, but it is a scalar RAS-commit port
  with no slot dimension and its own valid, so it cannot classify a
  per-slot update channel.

- A new br_type input port on the cluster. Rejected: it duplicates
  facts the update struct already carries, gives the FTB and uBTB
  fan-outs two independent sources that can disagree -- exactly what
  requirement 5 forbids -- and widens the boundary the FTQ has to
  drive.

- ftb_upd_* directly. Rejected: those ports are scalar, one per
  cluster, and w_upd_type_u0 is per slot. Slot 1's classification
  is not available on them.
