## 2. The rule changes for acceptance

I recommend accepting all seven. Notes on each:

1. **A1, the fallback at the speculative depth.** Accept. The IA stores
   the depth (dep) in the snapshot, not the offset n, and takes the
   committed depth (dcm) from the commit snapshot instead of counting
   it. Both are right: the IA's first build counted, and tb_ras showed
   the drift. It costs 8 bits per snapshot.
2. **B1, links never name a reused entry.** Accept. The task said "a
   link carries the allocation tag". The IA built something better:
   it kills the links exactly when an entry is reallocated, and keeps
   a generation tag only for the snapshot's TOSR entry. That is 16
   comparators per allocation and 4 bits per snapshot. Building it also
   found and fixed a real defect: a push landing on its own TOSR entry
   linked the entry to itself (tb_ras TC-74a). The 4-bit tag can alias
   after 16 reallocations within one snapshot's life. RS6 checks for
   that and has never fired.
3. **C1, predecode-found calls.** Accept. The IA also found that
   predecode never finds a return, because ifu_f3 flags a JAL only. So
   my hypothesis that C1 removes ret_pd was wrong.
4. **The undo of the restored block's own push.** Accept. The task
   didn't name it, but C1 needs it, and building it unasked is exactly
   the freedom you meant.
5. **TD#211 (b), the positional end clear.** Accept, with the IA's
   reasons. The clear states the rule whatever the slot placement does.
   ftq_resolve's view that runs one slot high is left as a training
   question and recorded.
6. **TD#211 (a), the backend redirect clear.** Accept. The IA applies
   it to every _self-clear redirect except RC_UNSPEC, because the FTQ
   cannot tell a trap from a mispredict except by cause. For a
   mispredict the resolution clears the same slots. This is my proposal
   applied correctly.
7. **The FTQ entry width,** 304 -> 316 bits at two slots, 20,224 bits
   for the array. Accept. The ftq_entry.sv header said 232 bits, which
   was wrong before this task.

**Physical design:** the restore path now carries the undo, the C1 pop
and push, and the generation test, and every allocation drives 16

THE SIX UNEXPLAINED CLASSES, DEFINED. 381 returns in the 25 runs. Each
definition is the classifier rule that assigns the class
(perf/src/harness/ras_class.h, classify(), lines 657-831).

Terms:
- R is the mispredicted slot-held return.
- C_T is the call that the reference stack names as R's match. The
  reference stack holds the committed path's calls.
- The window is every restore whose cycle lies after C_T's p2 and no
  later than R's p2.

The rules are applied in order, R1 to R10, and a class is assigned only
if no earlier rule fired. So every case in these six classes has already
passed four tests:
- R was predicted by the FTB.
- R made a p2 pop at its own position (R4).
- C_T made its push at p2, at p3 or by C1.
- That push was not dropped or undone, wrote the right address, and did
  not meet a saturated count (R5).

The definitions:
- depth (10), R6, ras_class.h:706. While C_T's reference entry was
  live, 32 or more entries (RC = RAS_COMMIT_ENTRIES) stood above it. The
  call depth is beyond what the commit stack can hold.
- pop_empty (11), R7, ras_class.h:709. R's pop returned not valid. The
  speculative stack was empty, and the A1 fallback had no frame
  (n >= the count).
- stale_below_bos (30), R8, ras_class.h:720-724. All three hold:
  - R's pop read the speculative stack, not the fallback.
  - The entry it read is C_T's own allocation index.
  - A later push reallocated that entry before R's p2, and the block of
    the evicted push had already committed. If that block had not
    committed, the class is wrap.
- fb_stale_top (113), R9, ras_class.h:794. All four hold:
  - The speculative stack was empty.
  - C_T had committed.
  - The commit-stack entry at the fallback index was pushed by a call on
    the path whose frame is already closed.
  - The return that closed that frame made a pop. If it made no pop, the
    class is ret_pd or ret_nopop.
- commit_lost (29), R9, ras_class.h:796. All four hold:
  - The speculative stack was empty.
  - C_T had committed.
  - The commit-stack entry at the fallback index is a live frame on the
    path, but not C_T's. C_T's own entry would be commit_addr.
  - No restore in the window rewound BOS or held an off-path operation.
- bos_rewind (188), ras_class.h:762, 796, 818, 824, 828. This is not a
  mechanism. It is the class given in place of fb_uncommitted (762),
  commit_lost (796), extra_closed (818), extra_offpath (824) or
  extra_deep (828) when a restore in the window has rewind set. rewind
  means the snapshot's BOS differs from the BOS it replaces, because
  blocks committed between the snapshot and its restore (ras_class.h:453,
  rc_rs_bos != rc_bos). In 796, 818 and 828 snap_offpath_op is tested
  first and takes precedence. In 824 a return to a block named after the
  redirect is tested first.
- The per-rule counts of bos_rewind (762, 796, 818, 824, 828) were not
  collected.

## Assumptions made not explicit in the prompt
- "n is in the snapshot" is taken to mean that what is restored is the
  depth from which n is formed. Storing n itself would go stale with
  every commit between the snapshot and its restore. The snapshot
  carries the speculative depth, and n is formed against the last
  committed block's depth.
- "The link tags" are a per-entry generation and a tag in the snapshot
  for its TOSR entry. Links inside the array are killed exactly on
  reallocation (16 comparators), which needs no per-link tag: a per-link
  tag aliases after enough laps, and a stale link can live long.
- C1's push uses the p2 rules, recursion match included, not RP7's
  missed push without it.
- TD#211 (a) applies to every backend _self-clear redirect except
  RC_UNSPEC. The FTQ cannot tell a trap at a non-branch from a mispredict
  by anything but the cause, and for a mispredict the clear is the
  resolution's own clear.
