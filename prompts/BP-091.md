# Task Overview

Retrofit loop_pred.sv from single-slot to NUM_PRED_SLOTS
prediction and update, per TD#105. This closes the last
predictor that does not present a per-slot interface.

The retrofit is a port-shape and storage change, not an
algorithm change. The per-slot prediction algorithm is
unchanged. What changes is that every prediction and update
port gains a slot dimension, the internal tables become
per-slot banks per TI6, and the pred_p0 output is renamed
pred_p1 to match the stage at which it is actually available.

bp_cluster.sv instantiates loop_pred and is therefore in
scope. Renaming a port and adding a slot dimension breaks the
instantiation; lint_bp_cluster would fail and block
completion. The rewire also removes two placeholders that
TD#105 records as consequences of the single-slot module:
bp_cluster gives slot 1 the uBTB prediction unconditionally,
and drives p2 loop metadata for slots above 0 to zero rather
than a real per-slot snapshot. Both become real in this task.

bp_cluster has never been simulated. Its changes here are
verified by elaboration and lint only. tb_bp_cluster is a
later task.

## Hypothesis

loop_pred can be retrofitted to NUM_PRED_SLOTS per-slot
prediction and update, with per-slot table banks per TI6 and
all slots indexed from the single p0 request PC, without
changing the per-slot prediction algorithm or the field sets
of lp_pred_t and bp_loop_meta_t.

If that holds, bp_cluster's slot-1 uBTB placeholder and its
zero-driven p2 loop metadata for slots above 0 can both be
replaced by real per-slot logic in the same task, and every
target in the bpu Makefile stays green.

## Background

loop_pred.sv is the only one of the eight BPU top-level
modules that is single slot. No port on it carries a slot
dimension. Both fe_decisions.md 2.1 and
ftq_bpu_interfaces.md section 4 describe the loop predictor
and the uBTB each presenting NUM_PRED_SLOTS predictions per
cycle at p1. The RTL does not.

Two consequences exist in bp_cluster today, both found during
INFRA-011 and BP-090 in session-063:

  - The p1 selection mux has no loop_pred producer for slot
    1, so slot 1 takes the uBTB prediction unconditionally.
  - The p2 prediction metadata group drives the loop metadata
    for slots above 0 to zero rather than a real per-slot
    snapshot.

The module also names its prediction output pred_p0 while the
value is available at p1. The rename is folded in here rather
than left as a separate testbench-touching task.

Session-063 retired the two-PC-range block model. There is no
slot-1 PC at p0: G8 and G17 are superseded, and the
pred_pc_p0 + 32 slot-1 lookup was removed from ubtb.sv by
BP-086. The per-slot ports on this module are a shape, driven
from one request PC, in the same way bp_cluster drives
sc.inp_pc_p2 per slot from a single staged p2 copy (TD#91).

TC13 curr_itr saturation -- run per slot
  Rules: Update behavior case 2, saturating increment.
  Setup: reset, allocate at 0xA000 way 0.
  Stimulus: taken-branch hit with curr_itr=max-1, then again with
    curr_itr=max.
  Expected: curr_itr max-1 -> max, then max -> max.
  Criterion: both lookups report curr_itr==max.

TC18 conf saturation -- run per slot (NEW, closes mutant M7)
  Rules: Update behavior case 4, saturating increment at
    LP_CONF_LEVEL.
  Setup: reset, allocate at 0xB100 way 0.
  Stimulus: correct exit with conf=LP_CONF_LEVEL-1, lookup; correct
    exit with conf=LP_CONF_LEVEL, lookup.
  Expected: cnf reaches max then stays at max; no wrap to 0.
  Criterion: both lookups report lp_conf==LP_CONF_LEVEL, and the
    second reports lp_pred_is_loop==1 (still trusted).

TC14 slot independence -- every ordered pair of distinct slots
  Rules: TI6 per-slot banks; Update Interface, channels independent.
  Setup: reset. BOTH slots seeded with the SAME entry at the SAME PC
    0x14000, so both address the same set and way of their own bank
    and "unchanged" is a real value, not the reset value. A
    pre-check asserts both slots start at curr_itr==1.
  Stimulus: read both slots; learning hit on slot a only with
    curr_itr=1, past_itr=9; read both slots.
  Expected: bank a changes, bank b does not.
  Criterion: slot a curr_itr==2 and past_itr==9; slot b curr_itr,
    past_itr and the WHOLE lp_pred_t identical before and after.

TC14B slot independence with a live decoy payload -- every ordered
  pair of distinct slots (NEW, closes mutant M4)
  Rules: Update Interface -- upd_p0[s] is ignored entirely when
    upd_valid_p0[s]=0, including when another slot's valid is high.
  Setup: reset, slot a seeded at 0x14A00, slot b at 0x14B00.
  Stimulus: in one cycle, a live learning-hit payload on slot a with
    upd_valid_p0[a]=1, AND a fully formed decoy payload on slot b
    (lp_hit=1, lp_pred_is_loop=1, actual_taken=1, curr_itr=3000,
    past_itr=4000, conf=max, age=0x5A, addressed at slot b's own set
    and way) with upd_valid_p0[b]=0.
  Expected: bank a takes its update, bank b is untouched.
  Criterion: slot a curr_itr==2; slot b lp_pred_t identical before
    and after.
  Rationale: TC14 leaves the quiet slot's payload at zero, so a
    write enable that ignores the slot still writes nothing. The
    live decoy removes that masking.

TC15 both slots predicting in the same cycle
  Rules: Prediction Interface timing -- any subset of
    pred_valid_p0 may be asserted, each slot with its own PC.
  Setup: reset. Slot s is seeded at 0x15000 + s*0x400 with
    curr_itr=s+1. A pre-check asserts the per-slot PCs do not alias
    in index-and-tag.
  Stimulus: one cycle with every pred_valid_p0 bit set and each slot
    carrying its own PC.
  Expected: no RAM change.
  Criterion: per slot, lp_hit==1, lp_curr_itr==s+1,
    lp_tag==tag_of(pc[s]), lp_idx==idx_of(pc[s]).

TC16 both slots updating in the same cycle
  Rules: Update Interface -- every channel processed independently
    in the same cycle, into its own bank.
  Setup: reset. Every slot seeded identically at PC 0x16000 way 0,
    so the only post-update difference is the payload itself.
  Stimulus: one cycle with every upd_valid_p0 bit set, slot s
    carrying curr_itr=10*(s+1), past_itr=100*(s+1), age=s+1, all
    addressed at the SAME set and way of their own bank.
  Expected: bank s holds curr_itr=10*(s+1)+1, past_itr=100*(s+1),
    age=s+1.
  Criterion: the three fields read back per slot match those values.

TC17 reset state of every bank
  Rules: Reset State section as delivered.
  Part A setup: reset only.
  Part A stimulus: 512 PCs swept, every slot looking up the same PC
    in the same cycle. Set coverage is accumulated and asserted.
  Part A expected: no RAM change.
  Part A criterion: per PC per slot, lp_hit==0, lp_victim==0,
    lp_age==0, lp_conf==0, lp_past_itr==0, lp_curr_itr==0,
    lp_curs==0, lp_curs_v==0, lp_pred_is_loop==0; and the sweep
    reached all LP_N_SETS sets (&seen).
    On a miss the DUT reports way 0 of the addressed set, so these
    fields ARE way 0 -- part A proves way 0 of every set of every
    bank is zero.
  Part B setup: reset, per slot.
  Part B stimulus: at set idx_of(0x80), fill one way at a time with
    tags 1..4, reading lp_victim before each fill. A pre-check per
    step asserts the probe tag does not alias the filler tag.
  Part B expected: victim reported 0, then 1, then 2, then 3.
  Part B criterion: lp_hit==0 at every step and lp_victim==w at
    step w. Priority 1 returns the lowest-indexed INVALID way, so a
    way left valid by reset would be skipped -- this proves ways
    1..LP_TBL_WAYS-1 were invalid too, which part A cannot show.

## Assumptions made not explicit in the prompt

A1. bp_cluster's own boundary ports lp_upd_valid_p0 and lp_upd_p0
were given the slot dimension. Requirement 9 names the instantiation
but not the cluster boundary. The instantiation cannot be driven per
slot from a scalar source without either replicating one branch's
update into every bank (wrong -- it would write another branch's
coordinates) or leaving every bank above 0 permanently unwritten
(which makes the per-slot prediction dead logic and the requirement
9 mux change meaningless). ftq_bpu_interfaces.md section 8 line 484
already states these ports are "per-slot after the TD#105 retrofit",
so this is a documented decision rather than a new one. bp_cluster
is a Deliverable and nothing instantiates it, so no file outside the
Deliverables list is affected. This is reported rather than treated
as a stop-rule blocker because it is a change inside a Deliverable
that a binding document already specifies.

A2. Slot dimension style. Requirement 5 says to follow the
neighbouring predictor ports in this unit, but constraint on file
access forbids reading ubtb.sv, tage*.sv, ittage*.sv, sc*.sv and
ras.sv. The style was taken instead from bp_cluster.sv, which is in
Context Loaded and whose internal nets must match those modules'
port shapes exactly. Those nets show two styles: ubtb uses a packed
descending array; tage, ittage, sc and ras use a packed vector for
per-slot valid bits and an unpacked ascending array
[0:NUM_PRED_SLOTS-1] for per-slot payloads and addresses. The
majority style was used. Recorded here as required by requirement 5.

A3. Documented reset state. The doc documented no reset state, so
TC17 had nothing to check against. The RTL's actual reset behaviour
was taken as the specification, written into the new "Reset State"
section of the doc, and then proved by TC17. This is a doc
completion, not an RTL change.

A4. Effort level in the Model header. The session model is
claude-opus-5[1m]. The effort level is not exposed to the session,
so the CLAUDE.md example label "normal" was used.

A5. Each of TC1-TC13 now begins with its own do_reset(). The
shipped testbench reset once and let TC1-TC7 share that start
state. CLAUDE.md requires that start state be established by reset
plus a known driven sequence and that no state be carried across
test cases, so a per-case reset was added. Every test keeps its
original intent and its original checks; only the starting point
became explicit.

## Decisions made not explicit in the prompt

C1. The cluster net w_lp_pred_p0 was renamed w_lp_pred_p1. The file
header states the naming convention as "internal nets carry a w_
prefix, stage registers an r_ prefix with the stage in the suffix".
After the port rename, a net named _p0 bound to a port named _p1 and
holding a p1-valid value would violate that convention and would be
actively misleading. This is a net rename inside a Deliverable, not
a port rename; decision 5's "leave every other port stage suffix
alone" is not touched.

C2. Two new cluster nets were introduced rather than binding
expressions inline: w_lp_pred_pc_p0 (the request PC replicated per
slot) and w_lp_pred_val_p0 (the request valid replicated per slot).
An unpacked per-slot array cannot be built by a scalar continuous
assign, which is exactly the reason the gen_slot loop already
exists; the PC driver was placed in that loop and the valid driver
alongside the existing tage and ittage replications.

C3. TC18 and TC14B were added beyond the requirement 7 list. Both
exist to close a mutant that survived pass 1. Requirement 11 asks
that survivors be reported as coverage holes; they are reported
above, and they were also closed, because leaving a known hole open
in a testbench delivered as green would misrepresent its strength.

C4. loop_pred's NUM_PRED_SLOTS default stays 1 rather than becoming
the package value. bp_defines_pkg is not a Deliverable and a module
parameter cannot default to a same-named package parameter without a
circular reference. Overriding at instantiation is the pattern ubtb,
tage, ittage and sc already use, is why -Wno-VARHIDDEN exists on
these targets, and satisfies decision 1's requirement that the
module elaborate at either value.
