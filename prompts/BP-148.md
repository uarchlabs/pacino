# Task Overview
The walker walks every mode of MMU-20 (BP-146). The ITLB does not yet:
it treats the 512 GiB and 256 TiB size codes as reserved, and it checks
every translated fetch address as an Sv39 one. This task builds the ITLB
in every mode and moves tb_fe_top onto the page-table builder, so that
programs can run in Sv48 and Sv57:
1. The ITLB installs, matches and invalidates 512 GiB and 256 TiB pages
   (ITLB-3, IL-7). Only 3'b11x is reserved.
2. The ITLB checks a translated fetch address against the current mode
   (ITLB-18). A MODE value that is not Bare, Sv39, Sv48 or Sv57 is
   checked as Sv39 (MMU-33).
3. tb_itlb tests each mode and both new sizes.
4. tb_fe_top's program writer builds its page tables with pt_build_pkg,
   in any mode. Every existing program gives its BP-147 result. The
   writer's helper names and fields stay, as wrappers, because
   examples/fe_demo calls them; tb_fe_demo is built, not run.
5. Three new tb_fe_top programs: sv48, sv57 and h57 (vsatp Sv57, hgatp
   Sv57x4).

Running every translated test under Sv57, and the weekly regression
over all modes, is BP-149.

  Every drained word was logged twice, once as word and once as direct, with the same

  reference to a class member. I moved the declaration and plog above wr64 and rebuilt.

  I did not look at the generated C++ or build a small reproduction. My best guess is

  guess; I didn't test it.

  same object as the caller, while pool is a separate object.

  - The draining member is deleted.

## Hypothesis
The ITLB's array is size-general already: an entry carries its size
code, and the compare masks the bits that size covers. Two new masks,

by hand, while pt_build_pkg (BP-146) already builds every mode and was
written to be drained into tb_fe_top's image.

## Assumptions made not explicit in the prompt
1. The 256 TiB case in tb_itlb (a). PA 0 is outside main memory, so it
   is not executable (MMU-15a). The first 4 KiB page of the only 256 TiB
   page therefore cannot answer "hit". G22 checks that the entry matches
   instead: the PMA refuses it, cause 1, and no walk starts (a miss would
   start one). G23 is the first main-memory page and does hit.
2. h57 and "the x4 root's top bits". A GPA that a VS-stage PTE or vsatp
   names has at most PTE_PPN_WIDTH + 12 = 56 bits. Through a VS-stage,
   the Sv57x4 root index (GPA[58:48]) therefore reaches entries up to
   0xFF only. Entries 0x100-0x7FF (GPA bits 58:56) need vsatp Bare. h57
   uses GPA bit 53 for code (entry 0x20) and bit 54 for the VS tables
   (entry 0x40). Both are at or above SV48X4_GPA_WIDTH and need the
   fifth G-stage level. h57 checks that the walker reads both entries.
3. sv48 and sv57 end with two faults: the non-canonical fetch the task
   names, then the sv39-style fetch of an unmapped page. Both are cause
   12.
4. MMU-33's ITLB half is built as the Binding states, because
   mmu_decisions.md still reads PROPOSED. I report it as built to the
   proposal.
5. A sign bit at or above VA_WIDTH leaves no bit to check (sx_mask
   returns 0). That cannot happen at VA_WIDTH 59.

## Decisions made not explicit in the prompt
1. One shared page pool (pt_pool) for every stage's table pages and the
   G-stage's backing pages. That is how the BP-147 writer allocated them
   (one pt_alloc), and it is what keeps every address unchanged.
2. Where BP-147 changed a G-stage leaf after placing it (D clear or W
   clear on a VS table page), the builder now places it with those
   flags (h_map_tf). The binding allows a direct write only for a word
   changed after it is mapped, and the builder can write this word
   itself. No direct PTE write remains in tb_fe_top.
3. Dropped: the zero fill of each new table page (old pt_alloc). The
   memory model reads an unwritten byte as 0 (W.rd8). The comparison
   (Other Notes 1) covers non-zero words only.
4. Added +PTLOG to the writer: a line per builder call and per word
   written, for comparing layouts across versions. It is off by
   default.
5. The mode used for satp, vsatp and hgatp setup comes from the built
   stage: models_reset uses W.ss.mode, set_h2_at uses W.vs.mode and
   W.gs.mode, and pt_vsonly uses W.vs.mode. A program sets the
   single-stage mode with use_smode before it maps anything.
6. tb_itlb check names: the new loops use pv_name() rather than ?: on
   two string literals. Verilator pads the shorter literal, which put a
   leading space in the name. The existing W group still uses ?:, and I
   left it unchanged.
