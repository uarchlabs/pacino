## Hypothesis
The IFU, the L1I and the front-end top are built and run end to end
for every predictor path (BP-121, BP-122). What is missing is
specified to the port and rule level but has no hardware: the L1I
has no invalidate port, the IFU's maintenance and uncached paths
are stubs, and no program exercises them. Building them against the
pacino copy of the l1i and running programs that use them will
expose whatever the specification and the existing RTL leave
inconsistent.

## Specific Requirements

STEP 1. The pacino l1i. Copy the emitted l1i
(tools/cachegen/output/l1i/, including l1i_pkg and its testbench)
into rtl/core/frontend/icache with its own Makefile and regression
targets, and switch fe_top and l1i_param_chk to the copy. Show the
copy passes the emitted testbench unchanged before changing it.
Then add:
- the maintenance ports of l1i_ifu_interfaces.md 10.1 with IF-28 to
  IF-32 and IF-42 (drain then clear; inv_line drains only a
  matching MSHR; fetch held while an invalidate is in flight);
- the uncached bit of IF-44 with L1I-24 (forced miss, no
  allocation, no replacement update; a merged cacheable request
  still allocates).

STEP 2. The IFU.
- The maintenance path of l1i_ifu_interfaces.md 11 (cmt_ifu_maint_*,
  ifu_cmt_maint_ack): IF-33 to IF-37, the line buffer clear of
  IF-36 after inv_done, and the interaction with a flush (6.1).
- The uncached path of ifu_decisions.md section 7: IFU-26 marks the
  block, IFU-22 gates the request on the commit pointer, IFU-23
  delivers one instruction at a time; never a prefetch (MMU-14).
- fe_top carries the maintenance group across the boundary (FE-17,
  backend group).

STEP 3. MMU-15b. The checker rejects at elaboration a region table
that marks a region executable but not idempotent, with a negative
lint target showing it.

STEP 4. Programs. Add tb_fe_top programs, each retiring its stream
exactly and each its own regression target, that between them
cover:
- FENCE.I after a store that changes code already fetched and
  cached: the new code executes after the fence and the old code
  does not;
- cbo.inval of one line holding code, then a changed line fetched;
- FENCE.I and cbo.inval with fetches in flight and with a redirect
  near them;
- uncached fetch from a page whose PTE marks it NC and one marking
  it IO, under sv39, including a branch into, within and out of
  the page;
- that no uncached request is presented while an older instruction
  is uncommitted, and that no uncached line is allocated, checked
  every cycle in every program.
The testbench backend models the commit-side producer of section 11
(A1 to A5 as stated there).

STEP 5. Properties. Each new rule above that a property can check
gets one in the unit's property file, following CLAUDE.md
Verification - assertions, shown firing on a scratch copy with the
rule's logic reverted.

STEP 6. Fix and rerun. Run every program, one simulation per
program. Fix what fails, with a failing check first, and rerun all
of them after each fix.

STEP 7. The end state. The task is complete when all of these hold:
- every program in STEP 4 retires exactly and is a regression
  target, and every earlier program still does;
- every rule named in STEP 1 to STEP 3 is built and has a check or
  property that fails when its logic is reverted;
- no uncached request is presented early and no uncached line is
  allocated, in any program;
- the cycles and mispredicts of the 19 earlier programs are
  unchanged, or each change is explained;
- no known correctness defect in the front end is open;
- tools/regress.sh passes.
If the end state cannot be reached, stop when the remaining items
all need decisions Jeff has deferred, and say which.
