# Task Overview

One end-state task in three parts, written by the method BP-121
established: the task is defined by what must be true when it ends,
not by a defect list, and the IA fixes what it finds.

A. The IFU is completed. The L1I is copied from the cachegen
   emission into the pacino tree and gains its maintenance ports and
   its uncached request; the IFU gains the FENCE.I and cbo.inval path
   and the uncached fetch path. Closes TD#119, TD#135 and TD#136.

B. The page table walker is built. There is no L2 TLB (MMU-1,
   reversed session-077); the walker serves the ITLB directly, sits
   outside the front-end top, supports Sv39 and nested Sv39x4, Svade
   and Svadu, Svnapot and Svpbmt at both stages, and reaches memory
   on its own port, answered by tb_fe_top's memory model. A
   guest-page fault gains an implicit-access kind for htinst.

C. A report, with evidence and a test for each item, of how the RVC
   expander, predecode and decode handle the RVA23 extensions that
   touch them: Zcb, Zcmop, Zimop, Zicbop's prefetch.i, and the
   atomicity of an aligned 32-bit fetch (Ziccif). Any gap found is
   fixed.

Every decision the task needs was ruled before it was written,
in sessions 076 and 077, and is in the planning documents named in
Context Loaded.

## Hypothesis
The front end can be brought to an end state in which every
mandatory RVA23S64 obligation that reaches instruction fetch has
hardware: instruction-cache maintenance (Zifencei, Zicbom), uncached
fetch under Svpbmt, and Sv39 and nested Sv39x4 translation (H through
Sha) with Svade, Svnapot and Svpbmt at both stages. Two of its
choices are this design's, not the profile's: the walk is done in
hardware, and Svadu, an expansion option, is supported beside Svade.
Each rule in the planning set can be built so that reverting its
logic fails a check or a property.

## Background
The L1I is the cachegen emission under tools/cachegen/output/l1i,
instantiated from that path by fe_top (fe_decisions.md FE-21). It
has no maintenance port and no uncached request (cachegen_decisions
.md CG-G2, CG-G8). The pacino cache RTL may depart from the
emission (CG-4, session-074), and session-076 ruled that this task
copies the l1i into the pacino tree and changes it there (CG-D1);
cachegen catches up later under CG-5, which needs this task's list
of differences.

The IFU's maintenance and uncached paths have been stubbed since
BP-118 (ifu_decisions.md 6.1, the paragraph after IFU-32). Uncached fetch now
goes through the L1I marked uncached; there is no second
instruction source (IFU-21 reversed session-076).

No walker exists (PROJECT_STATUS module row "page table walker",
Not started). The ITLB was built by BP-118 with its miss port, the
itlb_l2t_* group, answered by a testbench. That port now has a
real server: the walker. The port names keep l2t (ruled
session-077).

Session-077 confirmed full Svadu (MMU-6) and corrected two rules
against the privileged specification: the Svadu update is a compare
and store that restarts the walk on a mismatch (MMU-8), and PMA is
checked on every PTE access, not only on the final address
(MMU-12).

## Binding Previous Decisions
- The walker is NOT inside fe_top. tb_fe_top instantiates fe_top
  and the walker side by side and connects the itlb_l2t_* group
  between them (MMU-1a). The walker's CSR inputs are its own group,
  driven by the testbench (MMU-24a).
- There is no L2 and none is built here. The walker's memory port
  and the L1I's memory port are both answered by tb_fe_top's
  memory model, from one memory image (ptw_mem_interfaces.md
  WM-10). Nothing under tools/cachegen changes.
- Fetch never sets D in a single-stage or VS-stage leaf. The
  walker's D update for those exists for the future data-side
  client and is checked in the walker's own unit testbench (MMU-8).
  The G-stage D set by a VS-stage A update (MMU-8a) is a fetch
  case and is tested in tb_fe_top.
- The walker performs one walk at a time and answers a second
  request retry (MMU-U2, IL-6). The ITLB tracker stays at its
  default depth of 1 (ITLB-15).
- htval and htinst are not built; there is no CSR file. The task
  carries the guest physical address and its implicit-access kind
  to ifu_pd_pkt_t, where the backend will read them (MMU-29).
- A design choice not settled by the planning set is put to Jeff in
  session. If he is not there to answer, the IA takes its
  recommended option, records it in Results Capture as
  provisional, and continues; Jeff confirms or reverses after.

Problem 1. The pacino L1I.
  Done when:
  - the emitted l1i, its l1i_pkg and its testbench are copied into
    rtl/core/frontend/icache, and the unchanged copy is shown to
    pass the emitted testbench as a regress.sh target BEFORE any
    change is made to it;

    nothing in rtl/ still compiles the emission under tools/;

    l1i_ifu_interfaces.md 10 with IF-28 to IF-32 and IF-42, drain
    then clear, and the uncached request of IF-44 and L1I-24:
    a forced miss, filled and answered like any miss, never
    allocated and never moving the replacement state, while a
    cacheable request merged onto the same MSHR still allocates;
  - every difference between the copy and the emission is listed in
    Results Capture, for CG-5.

Problem 2. The IFU maintenance and uncached paths.
  Done when:
  - the IFU carries l1i_ifu_interfaces.md 11, IF-33 to IF-37 and
    IF-41, with the line buffer cleared after l1i_ifu_inv_done
    (IF-36), and fe_top carries the commit-to-IFU maintenance group
    across its boundary (FE-17, backend group);
  - a block whose effective type is not both cacheable and
    idempotent is issued to the L1I as an uncached request, never
    with the prefetch bit, presented only when every older
    instruction has committed (IFU-22), and delivered one
    instruction at a time (IFU-23), from the line already held or a
    new uncached request;
  - the PMP/PMA checker rejects at elaboration a region table that
    marks a region executable but not idempotent (MMU-15b), shown by
    a negative lint target that passes only when the check fires.

Problem 3. The page table walker.
  Done when:
  - a walker exists at rtl/mmu/ptw that meets mmu_decisions.md in
    full on the client port of itlb_l2tlb_interfaces.md and the
    memory port of ptw_mem_interfaces.md: Sv39 and Bare; nested
    Sv39x4 with all four combinations of vsatp and hgatp Bare or
    not (MMU-19 to MMU-23, MMU-26); the Svade/Svadu selection per
    stage (MMU-7, MMU-7a) and the compare-and-store with restart
    (MMU-8 to MMU-8b); Svnapot and Svpbmt at both stages including
    every reserved encoding (MMU-U6, MMU-U7); misaligned superpages;
    PMP and PMA on every access at privilege S (MMU-10d, MMU-12,
    MMU-12a); a PPN never truncated (MMU-28); the two-stage size
    (MMU-27); the GPA and its implicit-access kind (MMU-29,
    MMU-30);
  - the walker has its own unit testbench, which covers the D-bit
    update a data-side client would need;
  - the checker of MMU-10a is instantiated in the walker, taking an
    access type and a privilege as MMU-10d requires;
  - the ITLB and IFU carry the implicit-access kind (IT-6c,
    IFU-25) into ifu_pd_pkt_t (DCD-16); this is a package change;
  - tb_fe_top's memory model answers both memory ports from one
    image and can do what ptw_mem_interfaces.md WM-11 to WM-13
    require, and every earlier sv39 program now walks in RTL.

Problem 4. The programs.
  Done when tb_fe_top has a program, each its own regression target
  and each retiring exactly, for every case below, and every cycle
  of every program checks that no uncached request is presented
  before every older instruction has committed and that no uncached
  line is allocated.
  Maintenance:
  - code the L1I holds is rewritten in memory, FENCE.I commits, and
    fetch after the fence sees the new code;
  - cbo.inval of one code line, with the same check;
  - both with fetches in flight and a redirect near the operation.
  Uncached, under sv39:
  - fetch from an NC page and from an IO page (PBMT), branching
    into, within and out of each page.
  Walker, single-stage and two-stage:
  - every fault cause, 1, 12 and 20 (MMU-16), and each source of
    cause 1: PMP on a PTE read, PMP on the Svadu write, a page
    table outside cacheable coherent memory (MMU-12a), a PPN above
    bit 23 at a leaf and at a non-leaf (MMU-28), and a memory-port
    error (WM-7);
  - a guest physical address above bit 40 from a VS-stage PTE
    (MMU-28, MMU-30), and a guest-page fault of each
    implicit-access kind, checked at ifu_pd_pkt_t (MMU-29);
  - a 64 KiB NAPOT mapping at each stage, and a two-stage mapping
    whose stages differ in size (MMU-27);
  - every reserved Svnapot and PBMT encoding, and PBMTE clear;
  - Svade and Svadu at each stage, including henvcfg.ADUE and
    menvcfg.ADUE selecting differently in one nested walk, a
    VS-stage update that sets the G-stage D bit, a G-stage leaf
    without write permission for that update, and a compare that
    fails because the memory model changed the PTE (WM-11);
  - an ITLB invalidate while a walk is in progress (ITLB-14,
    IL-13, IL-14).

Problem 5. RVA23 Z* report.
  Done when Results Capture holds, for each item, the evidence from
  the RTL and a test that fails if the handling is broken:
  - Zcb: every Zcb encoding through the expander and decode, and
    whether BP-117's LLVM check had Zcb enabled;
  - Zcmop: c.mop.n, and whether the LLVM check had it enabled;
  - Zimop: mop.r.n and mop.rr.n decoded as the specification
    defines them, not as illegal;
  - Zicbop: prefetch.i accepted as the hint it is, and not
    mistaken for a control-flow instruction by predecode;
  - Ziccif: that no path delivers a naturally aligned 32-bit
    instruction from two separate reads, so its fetch is atomic, as
    rva23-profile.adoc states it, including across an invalidate.
  Any gap is fixed in this run.

Problem 6. The end state.
  Done when:
  - every rule named in Problems 1 to 3 is built with a check or a
    property that fails when that rule's logic is reverted, shown
    by reverting it on a copy outside the tree; every bound
    property is shown to fire;
  - every earlier tb_fe_top program retires exactly with cycles,
    retired instructions and mispredicts equal to the Problem 0
    baseline, or each change is explained;
  - no known correctness defect is open;
  - tools/regress.sh passes.
