## Decisions made not explicit in the prompt

1. LINT COVERAGE RETAINED RATHER THAN DROPPED. The choice was
   available and Problem 2 asked for it to be stated. Repathing
   the shared source lists keeps the assertion files in the lint
   builds. Rationale is under Problem 2: the bpu's lint_tage
   already lints a tb/ assertion file, so retaining is what the
   convention actually shows, and dropping would have removed
   lint coverage of ten files without any target failing.

2. THE PROOF METHOD WAS ELABORATION CENSUS, NOT INJECTION.
   Problem 3 allowed either and preferred the cheaper one if
   conclusive. The census names each assertion file and counts its
   elaborated property sites, which goes to zero if a file drops
   out of a build, so it is conclusive for the failure mode in
   question.

3. --json-only WAS USED FOR THE LINT-SIDE PROBE because
   --xml-only does not exist in Verilator 5.048 and --json-only
   cannot be combined with --lint-only. The probe uses the lint
   target's exact expanded command line with --lint-only replaced
   by --json-only, so flags, source list and top module are the
   lint target's own. The probe is a read-only side experiment; no
   Makefile target was changed to run it.

4. The property-site census counts source lines that emit a
   property failure message. It is a stable fingerprint for
   before/after comparison, not a restatement of the 73 bound
   property figure, and it is not offered as one. Where a count
   differs from the property count of a file, the cause is
   Verilator's handling of generate-replicated and multi-clock
   properties. The number that matters here is that it is nonzero
   for all ten files and identical before and after.
