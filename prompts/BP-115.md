## Background
The IFU's port groups toward the L1I cannot elaborate: their widths
are named in l1i_ifu_interfaces.md but declared in no package. The
emitted L1I declares the same quantities in l1i_pkg under cachegen's
names, and nothing makes the two agree.

The IFU writes one ifu_pd_pkt_t per halfword position to the ibuf
(16 wide, IB-1). The old predecode_pkt_t in decode_pkg is a
different, older struct that stays as it is for the built decode
until TD#143.

## Binding Previous Decisions
- TD#122 / TD-IF-1, ruled session-074: the L1I port parameters are
  declared in bp_defines_pkg and checked equal to the emitted
  l1i_pkg at elaboration. PPN_WIDTH becomes PA_WIDTH - 12.
- The check is a lint-only module with its own Makefile under rtl/,
  so tools/regress.sh runs it. Ruled session-074.
- DCD-16, ruled session-074: the bundle view is a NEW struct named
  ifu_pd_pkt_t. predecode_pkt_t is not touched. TD#143. DCD-16 and
  ifu_ibuf_interfaces.md section 4 include is_rvc, added
  session-074: expansion erases the instruction length and the
  backend needs it.
- ifu_pd_pkt_t is declared in bp_structs_pkg beside ftq_pd_info_t,
  not in decode_pkg. Ruled session-074.
- DCD-7: the control-flow classification is a 2-bit type (00 not a
  CFI, 01 conditional branch, 10 JAL, 11 JALR) plus is_call and
  is_ret as independent bits (DCD-11). It is the same encoding as
  ftq_pd_info_t.br_type, is_call and is_ret, and is NOT
  bp_br_type_e.
- DCD-15 and IB-4: the fault cause is one of four values: none,
  instruction access fault, instruction page fault, instruction
  guest-page fault.
- IB-3: ifu_pd_pkt_t.valid exists in the struct but is not driven on
  the IFU write port; the ibuf produces it on its read side. This
  task only declares the field.
- The FTQ index is FTQ_IDX_BITS wide, the same as
  ftq_resolve_t.ftq_idx, which the backend returns from this field.
