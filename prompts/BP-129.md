## Background
Each fact below was read from a file; check it against the tree.

- bp_history.sv declares `pred_taken [1:0]`, `pred_pc [2]`,
  `num_branches [1:0]` (0 to 2), `rollback_n [1:0]` (0 to 2),
  `rollback_tkn [1:0]` and `rollback_pbit [1:0]`. Inside, `ckpt_nb` is
  `[1:0]` per FTQ entry, `path_bit_0` and `path_bit_1` are separate
  signals, the first branch is written by an `if (num_branches >=
  2'd1)` block and the second by a separate `if (num_branches ==
  2'd2)` block that repeats every TAGE, ITTAGE and SC fold step, and
  the corrected rollback loops `for (int k = 0; k < 2; k++)`.
- In bp_history.sv the `[2]` in `TAGE_TBL_HIST[2]`, `IT_TBL_HIST[2]`,
  `SC_TBL_HIST[2]` and the matching `_FH` names is a TABLE number, not
  a slot. Those do not change.
- bp_history_interfaces.md HI7, bp_history_decisions.md section 9 and
  ftq_bpu_interfaces.md section 10 item 13 all record these literal
  widths as deferred, INFRA-011. bp_cluster.sv says the same in a
  comment above its compaction loop.
- bp_cluster.sv declares `w_hist_pred_taken [1:0]`, `w_hist_pred_pc
  [2]`, `w_hist_num_branches [1:0]`, and `w_rb_*`, `w_c2_*`, `w_c3_*`
  two wide. The compaction loop that fills the w_hist signals stops
  at `nb < 2`. The p2 and p3 correction blocks (rb_corr_p2,
  rb_corr_p3) loop over NUM_PRED_SLOTS but write two-bit results and
  stop at `n < 2`. The rb_corr_mux block chooses among the p3, p2 and
  FTQ bundles.
- The FTQ path is `ftq_rollback_n`, `_tkn` and `_pbit`, two wide, from
  ftq_npc.sv (`rollback_n` etc.) through ftq.sv's outputs and fe_top's
  wires to the bp_cluster inputs. `ftq_rollback_corr` is one bit and
  stays one bit. `ftq_rollback_slot_ex` and `ftq_rollback_slot_tkn`
  are already `[NUM_PRED_SLOTS-1:0]` and are not in scope.
- ftq_npc.sv's correction block builds the bundle from the redirected
  entry: every valid slot whose position is BEFORE the redirect
  position adds a not-taken bit, limited by `(n < 1)` to one such
  slot, then the redirected branch itself adds its resolved
  direction. So the bundle holds up to two bits AT EITHER SLOT COUNT.
- At NUM_PRED_SLOTS = 1, BP-128 D2 found that a block's second branch
  is not predicted and not held in a slot. If the backend
  mispredicts that second branch, ftq_npc's bundle is two bits: slot
  0, not taken, then the second branch. A one-bit port cannot carry
  both. Problem 3 is about this case.
- At 2, when both slots sit before the redirect position, the `(n <
  1)` limit leaves slot 1 out of the bundle. This task does not change
  that.
- bp_history_assert.sv H1 picks the bundle's last bit as
  `r_tkn[r_n[1]]` and tests `r_n != 2'd2`; both assume two bits.
  ftq_npc_assert.sv does the same at lines 223 to 226. tb_ftq_npc.sv
  checks `rollback_n == 2'd2` with `rollback_tkn == 2'b10` (line 671)
  and `rollback_n == 2'd1` (line 687). tb_fe_top.sv reads
  `w_hist_num_branches` and `w_hist_pred_taken` (lines 1427 to 1430)
  with two-bit constants.
- BP-128 left every lint and sim target with a `_1slot` twin that
  builds at 1; tools/regress.sh runs 261 targets.

Choices for the one-bit port, with the effect on the history the
predictors see (the block wrote ONE bit at p1, slot 0's; the
corrected rollback restores to that bit and writes rollback_n bits):
- A. The named branch's bit alone (slot 0's not-taken bit dropped).
  The block keeps one history bit, now the resolved direction and
  path bit of the mispredicted branch. The newest bit after a
  mispredict is the resolved direction, as BP-121 D14 / H1 / N11 /
  tb_fe_top "history after a mispredict" require. It is the bit a
  one-slot prediction writes when its slot holds that branch. Slot
  0's not-taken passage is lost from the history.
- B. Slot 0's not-taken bit alone (named bit dropped). History looks
  like a fall-through block: the mispredicted branch's resolved
  direction never enters the history, against BP-121 D14; H1, N11
  and the tb_fe_top check would have to be weakened.
- C. Clear rollback_corr in this case (restore past the bundle as
  before BP-121). Same history effect as B, plus the checkpoint is
  not rewritten. Reverses BP-121 for this case.
- D. Carry both bits (a NUM_PRED_SLOTS + 1 bundle at 1). History gets
  two bits for a block whose prediction writes one, so the corrected
  history does not match what a correct prediction of the same block
  writes. Against BP-128 D1 (ports sized by NUM_PRED_SLOTS). The
  baseline at 1 behaves as D (its ports were two wide).

choose without waiting). Reason: it is the only choice that fits the
NUM_PRED_SLOTS-wide port, keeps the resolved direction as the newest
history bit (D14), and keeps one bit per block as the prediction path
writes. Implemented as the limit (n < NUM_PRED_SLOTS - 1) on the
not-taken bits (ftq_npc.sv:410); the bundle is at most NUM_PRED_SLOTS
bits. At 2 the limit is (n < 1), the bundle unchanged: all 2-slot
