```

  u1   RAM write completes
```

## Assumptions made not explicit in the prompt

1. Queue-status ports are presented at the cluster boundary rather
   than left dangling. Requirement 3 names "the configuration and
   status sidebands" as part of the port list, and interfaces
   section 7 says the queue status ports are "driven out of the
   cluster". The binding decision that they "tie off in this task"
   is read as: no arbitration logic inside the cluster consumes
   them. They pass straight through to bp_cluster outputs.

2. tage and ittage both declare pq_not_full and upd_rdy with no
   predictor prefix (TD#49). Two same-named ports cannot both reach
   one boundary, so the cluster boundary prefixes them:
   tage_pq_not_full, tage_upd_rdy, ittage_pq_not_full,
   ittage_upd_rdy. These are NEW cluster-boundary names, which
   interfaces section 2 permits.

3. Both prediction slots receive the same request PC for the TAGE
   and ITTAGE input structs. Requirement 6 says "from the request PC
   and FTQ index", singular, and the FTB is not internally slot
   split: one lookup describes one 32-byte block and br0/br1 are
   both fields of that block (interfaces 5.1). ubtb.sv computes its
   own slot-1 offset internally; the cluster does not add one.

4. ckpt_wr_en, rollback_valid and rollback_ckpt_idx are internal
   tie-offs, not cluster input ports. Interfaces section 8 marks
   ckpt_wr_en "NEW driver at cluster", and rollback is driven from
   the cluster's own redirect derivation (section 6). Neither
   producer exists yet, so both tie off inside the module rather
   than being exported for the FTQ to drive.

5. -Wno-UNDRIVEN on lint_bp_cluster. The Constraints list no
   session-specific suppressions, but the binding decision requires
   the section 6 redirect outputs to be declared and undriven, and
   the p1 outputs cannot be driven without the excluded selection
   mux. The suppression was verified to mask exactly 8 signals and
   nothing else -- see Other Notes.

## Decisions made not explicit in the prompt

1. No always_comb anywhere, not even for the struct field
   assignment requirement 6 permits. A block reading only module
   inputs is classified stl_sequent by Verilator v5.048 and does
   not re-evaluate after simulation start (CLAUDE.md). Every
   per-slot struct field is a continuous assign inside a generate
   for-loop instead. This is stricter than the constraint requires
   and removes a live simulation hazard for tb_bp_cluster.

2. ras_fall_through_p2 is wired to ftb_pft_addr_p2 rather than
   tied off. Interfaces 5.1 states pft_addr is the fall-through
   address and 5.4 lists ras_fall_through_p2 as a p2 input; both
   are p2 signals, so this is a real structural connection at the
   correct stage, not a tie-off.

3. ras_pc_p2 is driven from ftq_pred_pc_p0 per TD#101, and
   sc.inp_pc_p2 from ftq_pred_pc_p0[VA_WIDTH-1:1] per TD#91. Both
   are p0 signals reaching p2 ports. No pipeline register exists
   because the task forbids state. Flagged under Deferred Work.

4. ckpt_wr_idx is driven from ftq_pred_idx_p0 rather than tied to
   zero. The strobe is 0, so the value is inert, but routing the
   real index documents the intended connection and leaves only the
   strobe for the FTQ allocation task to add.

5. Internal nets carry a w_ prefix, matching the ftb.sv and tage.sv
   convention for structural tops.

6. File order in lint_bp_cluster is packages, lib components, leaf
   modules, predictor tops, then bp_cluster.sv last. tage.sv,
   ittage.sv and sc.sv set `default_nettype none and never restore
   it, so bp_cluster.sv is compiled under that directive. Every net
   and port in bp_cluster.sv is explicitly declared, so this is
   safe and was confirmed by the clean lint.

### Generate block style

for-loop over the prediction slots, named gen_slot. The loop body
holds continuous assigns only: no nested generate, no conditional
generate, no instances, no always blocks. It exists solely to index
the unpacked per-slot port arrays [0:NUM_PRED_SLOTS-1], which a
scalar continuous assign cannot span. The style is documented in
the bp_cluster.sv file header and matches the existing gen_pred
loop in ubtb.sv.
