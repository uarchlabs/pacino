## Hypothesis
The loop predictor is never used because each update rewrites the
entry from a snapshot taken at prediction, and many iterations are
predicted before the first update lands, so the count never
settles (BP-121 Deferred Work). An update that reads the entry
before writing it, with each prediction carrying its iteration
number and a speculative iteration count at prediction, will let
the count settle and the loop exits be predicted.
