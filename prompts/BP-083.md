## Decisions made not explicit in the prompt

1. The $fatal message string for WC-TARGET was updated from
   "FAIL entry_a.target" to "FAIL entry_a.slot[0].target".
   Requirement 2 says to keep the message and change only what the
   check references. Read literally, the identifier inside the
   message is part of what the check references, and leaving it as
   entry_a.target would print the name of a field that no longer
   exists -- a defect in a diagnostic. The message form, format
   specifiers, and argument structure are unchanged. Flagging it
   here because the other reading is defensible.

2. The two new width checks were appended at the end of the
   width-check block rather than inserted next to the target
   check. Appending guarantees no existing check shifts position,
   per requirement 6.

3. IND-SCAL (slot writes do not disturb the block-scalar fields)
   was added. Requirement 4 asks only that one slot not disturb the
   other. The scalar fields sit adjacent to the slot array in the
   packed layout and are exposed to exactly the same class of
   defect, and this is the check that would catch a bad field
   ordering in a future edit to bp_ftq_entry_t. It is an addition,
   not a change to an existing check.

4. SLOT_BITS and ENTRY_BITS are localparams built from the named
   package parameters and $bits() of the two enum types, not
   literal 52 and 156. A parameter change (e.g. NUM_PRED_SLOTS to
   1, or FTQ_CONF_BITS retuned) tracks automatically; a field
   added or removed still trips the check. Per the CLAUDE.md rule
   preferring named parameters over magic numbers.

5. Slot 1 and second-pattern constants are localparams
   (SLOT1_TGT, SLOT1_CONF, SLOT0_TGT2) rather than inline
   literals, so the drive value and the expected value in the
   read-back check cannot drift apart.

6. The negative-mutation validation was run on a scratch copy
   outside the repository. No file outside the Deliverables list
   was created or modified in the tree.
