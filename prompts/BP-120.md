## Decisions made not explicit in the prompt
- TD#157 NEEDS STATE. The FTB valid cannot be gated on the slot's
  acceptance: the fan-out presents the predictor requests only under
  ftb_sched_rdy, sc_upd_rdy is a grant of the SC request, upd_acc reads
  sc_upd_rdy, and ftb_sched_rdy reads the FTB valid (5.7.3 S6). One
  flag per channel plus the branch identity (6 + 4 bits) breaks it.
- The flag is qualified by the branch identity so that a replaced
  resolution still trains the FTB (tb_ftq_resolve replaces held ones;
  R17 caught the unqualified first version).
- TD#158: a channel loses to an older channel naming its slot whether
  or not the older is accepted that cycle (strict order). Placement in
  passes rather than rank order (Verilator ALWCOMBORDER and LATCH on the
  rank-ordered loop). A loser presents no FTB update (so TD#157's flag
  is not involved).
- FTB conditional mapping: the stored position is searched in BOTH
  fields before the port slot is used (case 1 above), so a branch whose
  slot index moved between predict and update still trains in place
  (tb_ftb F3). Case 2 prefers a free field over the field the slot
  names, per 5.1 ("a branch field free: write it into the free
  field").
- uBTB: only the field br_idx names is compared (the uBTB maps br_idx
  to the field directly and does not reorder; ubtb_interfaces.md).
- RAS: on the sentinel skip (the wrap) the new entry's nos is BOS, not
  TOSR. With nos = TOSR the wrap would link the new entry into a chain
  through slots the wrap is reusing (a cycle that never reaches BOS);
  nos = BOS keeps the 3.2 overflow effect (one reachable entry, then
  the commit fallback). Proposed text below.
- RAS undo-pop restores the registered pre-op TOSR (3.2 ruling) also
  for a recursion-decrement pop: TOSR stays, the count stays lost
