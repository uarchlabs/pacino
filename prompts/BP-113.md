# Task Overview

TD#139, a correctness defect. In a redirect cycle the index leaving
at p0 is the PRE-rewind alloc_ptr, while ftq_npc presents the
redirect target on the same cycle. The target block is written at p1
to an index the redirect squashes and is never fetched; the next
index issued holds target+32, so THE FIRST BLOCK OF THE CORRECTED
STREAM IS LOST. Instructions that must execute do not.

It applies to every redirect cause and predates BP-112, which found
it with a tb_ftq probe and did not fix it. 670 FTQ checks never saw
it: tb_ftq D9 checks the index a redirect produces and not the PC
that comes back.

ftq_decisions.md 5.2 already states the rule the fix must satisfy --
the index committed at p0 is the one allocated. The redirect cycle
is where that stops being true.

## Background

alloc_idx output (ftq.sv:372, and the header comment at line 18).
ftq_ptr rewinds alloc_ptr per 5.5 R1 -- to K, or K+1 when the naming
entry survives -- and that rewind is visible the cycle AFTER the
redirect. The p0 request in the redirect cycle therefore carries the
old value.

Confirm all of the above against the RTL. The probe is BP-112's and
the line numbers are from its read.

SECOND EFFECT, from ftq_decisions.md 5.1: the fetchable frontier is
the gap minus the requests in flight between p0 and p1, which
ftq_shadow counts. The squashed in-flight request is counted against

stalls TWO cycles where 5.1 and ifu_decisions.md IFU-27 say one.

## Assumptions made not explicit in the prompt
- A1 "The next fetch issued" after a predecode redirect is the refetch
  of K (W3), so the target is checked on the first NEW entry fetched
  after it (G7/G8). For backend redirects it is the first fetch.
- A2 The redirect-cycle fetch request itself is excluded from "next
  fetch issued". Its handshake is dropped (TD#138, out of scope), and
  tb_ftq's IFU model cannot tell a dropped handshake from an accepted
  one, so capture starts the cycle after the redirect.
- A3 Translation latency is counted from the redirect cycle (cycle 0)
  to the first cycle ftq_ifu_xlate_val presents F. The "one cycle"
  of 5.1 / IFU-27 is read as that count for the front-end case.
