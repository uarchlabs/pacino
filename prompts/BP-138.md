## Summary
Status: complete (regression RESULT: PASS, see below). Header Status
box not ticked: the IA writes only the Model field outside RESULTS.

D2 (RAS) root cause: the empty test TOSR == BOS is right only while
nothing moves BOS under an empty stack, and a commit does. A call
pushes X (link to BOS), its return pops X (TOSR back to BOS, empty),
then the call commits and BOS becomes X. TOSR stays on the old BOS
slot, TOSR != BOS, the stack reads non-empty, and the next return pops
the old BOS slot (fd07: the sentinel, 0x0) and follows its stale link.
Of the three readings in the Background, the defect is the second:
TOSR must move with BOS. That alone is not enough, so the fix has
three rules (ras.sv, THE BOTTOM):
  1. a push onto an empty stack, or the sentinel skip, marks its entry
     bottom (spec_bot, 1 bit per entry); the pop that removes a bottom
     entry sets TOSR to BOS as it is then, not to the link;
  2. a commit that moves BOS while TOSR == BOS moves TOSR with it;
  3. a p3 undo of an operation that began on an empty stack restores
     TOSR to BOS as it is at the undo (p3_pre_empty_q).
Empty stays TOSR == BOS. A first fix (empty = TOSR older than BOS in
TOSW allocation order, reading 3 of the Background) was built and then
withdrawn in this run: new property RS3 fired in tb_fe_top region, and
the trace showed that after a sentinel skip the old BOS slot reads
younger than entries allocated before the skip, so a later commit can
make a stale slot read held again. See Decisions.

D1 (bp_cluster): option b, PROVISIONAL. When the FTB answers with a
jump and every slot holds a conditional, the block ends at the jump
PC (w_pft_p2 = w_jmp_pc_p2, condition w_jmp_cut_p2). The next block
starts at the jump; the FTB window of that start sees the jump first
(ftb_decisions.md 4.6 R-1, O-3b) and the cluster places it in slot 0.
No FTB, uBTB, package or port change.

fd07: no valid p2 pop below 0x8000_0000 at either slot count (4 -> 0
at 2 slots, 7 -> 0 at 1 slot). fd07 passes in the 1-slot scratch
build, max_rctr 3 (was 0, FAIL). Backend mispredicts unchanged (61 at

- D1 option b, PROVISIONAL (ruling: IA chooses, records as
  provisional). Reasons: it changes neither the FTB entry shape nor
  the placement (TD#179 untouched), nor the FTB or uBTB; every branch
  the entry holds stays predicted. Option a drops the youngest
  conditional, so at 1 slot every {conditional, jump} block loses its
  conditional for good (never predicted taken, never in a slot to
  train). Option c moves the split into FTB allocation, where
  ftb_decisions.md 3 measured that a split end differs from another
  start's recorded end in 228 of 228 such blocks at one slot
  (contention for the shared pftAddr, TD#168). Cost of b: one extra
  prediction block on a path through such a block when its
  conditionals are not taken.
- The block ends at the jump PC, not just after the last placed
  conditional: both satisfy "no later than the jump's PC"; the jump PC
  makes the next block start at the jump, so the jump is that block's
  slot 0 and nothing is fetched twice.
- D2: the empty test stays TOSR == BOS, kept exact by the three rules.
  A first fix, empty = TOSR not allocated after BOS in the order TOSW
  allocates ((TOSW - 1 - p) mod 16), passed tb_ras and tb_bp_cluster
  but RS3 fired in tb_fe_top region at both slot counts. Trace: a
  sentinel skip (TOSW lapping BOS) passes the BOS slot without
  allocating it, so modulo TOSW that slot then reads younger than
  entries allocated before the skip. A later commit that moves BOS to
  one of those entries while TOSR is on the old BOS slot makes the
  stale slot read held: the D2 defect on the wrap path. The RS3 firing
  in region itself was a model error (the model counted the skip as an
  allocation, fixed); the hole it pointed to is real and is why the
  first fix was withdrawn. The three rules do not depend on allocation
  order and hold across the wrap.
- Bottom is an explicit bit per entry (16 flops), not a self-link
  encoding: the link keeps its 3.2 meaning (the BOS of the push on an
  empty stack or a skip), so the link checks of TC-29..33 and
  tb_bp_cluster M1 stand unchanged.
- RS2 / RS3 are checked only for a slot whose pop reads TOSR as the
  cycle starts (no p3 repair that cycle, no RAS operation in a lower
  slot); the other cases read a working top the model does not track.
