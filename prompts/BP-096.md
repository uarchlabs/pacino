## Background

Session-064 verified bp_cluster above the unit level and then found
that several of the suites reporting on it could not fail.

Two mechanisms were involved and they are independent.

FIRST, the failure exit. $finish and $finish(1) both produce exit 0
under Verilator v5.048. Seven testbenches used one of them as their
failure path, so a run that printed failures reported success to
make. BP-086, BP-094 and BP-095 found and fixed all seven. No count
changed -- the checks were correct throughout -- but none had ever
been enforced. $fatal(1) is now the settled failure exit.

SECOND, the bind form. tb_tage.sv line 285 reads

    bind u_dut tage_assert #( ... )

u_dut is the tb-scope instance name, not a module name. Verilator
5.048 accepts the form, instantiates nothing, and emits no
diagnostic under -Wall. tage_assert therefore does not run in
sim_tage, sim_tage_fast, lint_tage or cov_tage.

Line 294 compounds it. The port list connects assert_inhibit to
tage_assert_inhibit, which is not declared anywhere in tb_tage.sv.
It compiles today only because the dead bind means the port list is
never elaborated. BP-095 proved this by changing line 285 alone and
getting a compile failure.

BP-095 fixed the identical defect in tb_tage_manual.sv and verified
it live afterwards by forcing an assertion. Two defective binds were
found in the two files that happened to be opened for other work. No
sweep has been done.

A third item is smaller and adjacent: ittage_assert_bind.sv is
compiled by no Makefile target. tb_ittage.sv carries an equivalent
inline bind, so sim_ittage is believed correct, but the file is dead
weight that reads as coverage it does not provide.

A fourth is a different failure shape. tb_ittage_cntrl, tb_ittage,
tb_tage_tasks and tb_tage_manual have no watchdog. A DUT that never
asserts ready hangs make rather than failing it. That is not a false
green, so BP-095 left it out of scope. tb_ittage_table has a
watchdog and it is fatal.

Finally, an unreconciled number. BP-095's target tables report
sim_bp_cluster and cov_bp_cluster at 407 checks, in both its
baseline and its final run. BP-094 reported 973 for both, and 973 is
what the target is believed to print when run directly. BP-095 did
not modify tb_bp_cluster.sv, and its other 45 rows match BP-094
exactly. 407 matches neither 973 nor BP-093's 530 for groups A-F.
The cause was not determined by either task.

declaration changes nothing and the fix is to qualify the reference.
