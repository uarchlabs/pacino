- rtl/Vars.mk: `RVA_EXT_TOOLS ?= /usr/local/riscv-embecosm-embedded-
  ubuntu2204-20250309/bin` (?= so the environment or the make command
  line can override it), plus `need_ext_tool`, a recipe line that fails

  RVA_EXT_TOOLS (rtl/Vars.mk) to the directory that holds it".
- ifu Makefile: RVC_ORACLE_TC removed; oracle_ifu_rvc_exp checks
  llvm-objdump and clang, then passes $(RVA_EXT_TOOLS) to the generator.
- decode Makefile: CLANG_TC removed; asm_dec_words checks clang and runs
  $(RVA_EXT_TOOLS)/clang.
- gen_ifu_rvc_exp_oracle.py: GNU objcopy is no longer used. clang
  assembles the 49152 encodings as raw `.insn 0x....` into the input
  object (its .text is checked byte for byte against the encodings), and
  the re-encoded words are read from clang's object by a stdlib ELF
  reader (the one chk_dec_words.py uses). The regenerated hex is
  byte-identical to tb/ifu_rvc_exp_oracle.hex (cmp, and the target
  passes).

Tools needed per target, before -> after:
  oracle_ifu_rvc_exp: llvm-objdump, clang, riscv64-unknown-elf-objcopy
    -> llvm-objdump, clang.
    llvm-objdump IS the oracle (its printer's RVC expansion), and clang
    re-encodes that expansion. Both are needed, or it is no longer the
    LLVM oracle BP-117 recorded. objcopy only converted raw bytes to and
    from ELF, which clang and Python now do.
  asm_dec_words: clang -> clang (the assembler under test is the point
    of the check).
  (clang is clang-21 through the bin/clang symlink, as before.)

### Problem 4: the decode speed-up (TD#131)
EXPLAINED: ccache. The 5.048 install's verilated.mk sets
`OBJCACHE ?= ccache`. The 5.020 install (/usr/local/share/verilator)
sets `OBJCACHE ?=` (empty). With each install's default, the generated
compile line is "g++ -Os ..." under 5.020 and "ccache g++ -Os ..." under
5.048 (make -n -f Vtb.mk). The unit Makefile's make -n output differs
only in the verilator path. OBJCACHE is not set in the environment. So
moving decode from 5.020 to 5.048 turned on ccache, and with a warm
cache the C++ compile, which is most of a build, is skipped.

5.020 cannot build today's tb_instr_decoder ("%Error-UNSUPPORTED:
