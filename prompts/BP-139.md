# Task Overview
TD#179, first of two tasks. Requirement (Jeff, 2026-10-18): every
branch is predicted, at every slot count. NUM_PRED_SLOTS sets how many
branches one prediction block carries, which is prediction bandwidth
into the FTQ. It does not decide whether a branch is predicted.

Two defects at NUM_PRED_SLOTS = 1, found by an interactive IA session
on 2026-10-18 (tree 0599061):

D1: a conditional the FTB holds in br1 is in no slot. The block's
predicted path runs past it as if it were not taken, so it is never
predicted. BP-138 fixed the same fault for the jump field only.

D2: when that conditional resolves, ftq_resolve places it in slot 0,
which holds the first conditional, and TAGE, SC, LP and ITTAGE are
trained with the first conditional's metadata. The same thing happens
at two slots to any branch the entry does not hold behind two
occupied slots.

This task builds the cluster cut for any branch the FTB reports and no
slot carries (option A), and stops table-predictor training through
another branch's slot (item C). BP-140 follows with per-start FTB and
uBTB entries and the block split at update.

  else the last slot. At one slot, with slot 0 holding a conditional

  is never predicted from that start.

  ftq_entry.sv about 352-353), replacing the occupant. The backend
  resolves out of order, so the occupant can resolve after this write.
  By then its position no longer maps, and it is placed in turn.

## Decisions made not explicit in the prompt
- PROVISIONAL: the placed-slot write into an occupied slot (Binding
  Previous Decisions, "the IA chooses"). Rule: write only when the
  placed branch is a taken DIRECT_CALL, INDIRECT_CALL, RETURN or
  RETURN_CALL, or when it ends the executed block (taken or
  mispredicted) and the occupant is at a later position. Reasons:
  (1) the commit walk (ftq_entry 5.4) commits the RAS operation it
  finds in the slots, so a taken RAS op must be written; (2) an
  occupant after a block-ending branch is wrong-path and must not
  reach the commit walk (e.g. a predicted taken call), so it is
  replaced as before; (3) every other occupant is on the executed
  path and keeps its slot, so it maps and trains with its own
  metadata when it resolves after the placed branch (K3, L1). Cost:
  an occupant at an earlier position than a placed taken call or
  return loses its slot; resolving later it is placed with item C (no
  table training) (K4). That needs the first execution of a call or
  return the FTB does not hold behind every slot's conditional.
  Rejected: a per-entry record of the displaced occupant (needs
  allocation-time clearing, a port and FTQ_DEPTH x 6 bits);
  never writing an occupied slot (the commit walk would miss calls
  and returns).
