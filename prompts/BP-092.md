# Task Overview

Two boundary closures ruled by Jeff in session-064, done
together because both land on bp_cluster and on the same
p1/p2 paths.

TD#106. lp_pred_t survives; bp_loop_meta_t is retired.
The two types carry the same thirteen fields in different
declaration order with two spelled differently
(lp_past_itr / lp_pst_itr, lp_curr_itr / lp_cur_itr).
bp_cluster maps between them field by field in lp_to_meta().
Retiring bp_loop_meta_t deletes that function rather than
rewriting it, and removes a type pair where a bit-level
recast would compile and scramble every field.

TD#108. The p1 output group gains the block fall-through.
Today the group carries val, idx, the slot array and the RAS
snapshot. The FTQ derives the successor from the slot array,
but on a not-taken block it needs the block end, and that
value stays inside the cluster. Exposing it also closes an
observability hole for the later testbench: the p1 redirect
operand cannot otherwise be checked directly.

bp_cluster has never been simulated. Nothing instantiates it
and lint_bp_cluster is the only target that reads it. The
claim for the cluster in this task is elaboration and lint
clean, not that either change was exercised.
