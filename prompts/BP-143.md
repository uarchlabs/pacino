## Binding Previous Decisions
Jeff, session-084:
- TOSR below BOS is not a fault (ras_decisions.md 3.2). A held entry
  is a chain entry (12.12 IV1): an entry a push wrote, at TOSR or
  reached from it by the links (nos, or BOS for a bottom entry),
  above BOS in allocation order or below it.
- A valid pop returns a chain entry (12.5 PO7): never the BOS
  sentinel and never a slot no push on the chain wrote (fd07: TOSR
  left on an old BOS slot when a commit moved BOS, BP-138). The one
  exception is the wrap: once the allocator has gone round the buffer
  since an entry's push, the entry may have been reused, and its pop
  returns the reusing push's address. That is allowed (PU3, RE7) and
  counted, not failed. An entry below BOS is reused before the
  sentinel skip, which guards only BOS.

  allocation sequence per index and its own record of which
  allocation each link and TOSR refer to. It reads the DUT only to

  TOSR and BOS.
