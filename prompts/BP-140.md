# Task Overview
TD#179, second of two tasks. Issue after BP-139 is accepted.

BP-139 makes every branch the FTB stores predicted, through a cut at
p2 in the cluster, and stops table-predictor training through another
branch's slot. Two costs remain:
- the uBTB's p1 end does not match the cut, so a cut block costs a p2
  redirect each time it runs;
- a branch the FTB entry has no field for (a third conditional at two
  slots) is never stored, so it is never predicted.

Both come from the FTB and uBTB entry being shared by every start PC
in a 32-byte region (ftb_decisions.md 4.6, TD#168). A block split
written at update would compete with other starts for the one
pftAddr (BP-131: 228 of 228 one-slot cases).

Jeff (2026-10-18) chose the XiangShan approach for the highest
estimated performance:
- FTB and uBTB entries are keyed by the full block start PC, so each
  start has its own entry;
- the block is split at update, so an entry never holds more branches
  than NUM_PRED_SLOTS and its end stops at the last branch it holds.

The BP-139 cluster cut stays as a backstop. Training stays at resolve.

## Hypothesis
With one entry per start PC, a split end written at update has no
other start to compete with. The FTB and uBTB then store the same end
for each start. The cut block's p2 redirect goes away, every branch
gets an entry at the start where it is first, and the TD#168 rotation
of two jumps through one region's jump field ends. The cost is more
entries per region and set pressure from starts that used to share
one entry. That is measured, not assumed.

## Background
State expected at the start, after BP-139 (Problem 0 confirms it):

  slot count (ftb_decisions.md 4). Update field mapping:
  ftb_decisions.md 5.5. When both conditional fields hold other
  branches, a field is replaced, and the block end written is the
  update's (5.5, cases 3 and 4). Nothing shortens the block.
- bp_cluster: BP-139's cut. A block ends at the PC of the first branch
  the FTB reports that no slot carries.
- ftq_resolve: BP-139 item C, plus the BP-119 placement rule for a free
  slot.
- BP-131 (tb_fe_top, 36 programs): blocks with more branches than
  slots, 9 at two slots and 243 at one. A split end would differ from
  another start's recorded end in 228 of 228 one-slot cases.
- TD#168 (BP-121, BP-120): coro's two jumps in the 0x600 region take
  turns in one jump field and both mispredict, 39 mispredicts.

XiangShan split rule (FTBEntryGen):
- On a hit where the new branch does not fit, pftAddr becomes the
  offset of the branch that falls out: the new branch if it is the
  youngest, else the old last branch.
- The jump's call, return and jalr bits are cleared.
- The branch that falls out becomes the first branch of the next
  block, which starts at its PC. It gets its own entry when it
  resolves in a block from that start.

end (its block's predicted end) is not written: an end moves only to a
jump's resolved end or a split point, and a resolution at or after the
end (or after the stored jump) changes nothing, so the entry is the
same whatever order the branches of a block resolve in (PROVISIONAL,

## Assumptions made not explicit in the prompt
- "Identified by its block start PC at 2-byte granularity ... differ
  anywhere in VA[39:1]" is met by (index, tag) together: the index is
  VA[13:5] with VA[4:1] XORed in, the tag VA[39:14] and VA[4:1], so
  VA[13:5] is recovered from the index and VA[4:1]. VA bit 0 is always
  0 for an instruction start.
- "The end becomes the PC of the lowest-position branch not kept" is
  applied whatever the kind of that branch (a conditional or the jump),
  and a stale or out-of-order resolution after a split leaves the
  entry: a resolution at or after the end, or after the stored jump,
  is not in the block the entry describes.
- "Two starts ... map to one set under the starting index": every
  start of one region, VA[13:5] being the region index.
- The BP-131 contention count is re-measured in tb_fe_top (counter
  BP140 "over / other start / split end differs") with BP-131's
  definitions (prompts/BP-131.md P1(a), P3, read with Jeff's
  permission): an executed block is a run of retired instructions of
  one FTQ entry; an entry instance is an FTB way from one allocation to
  the next; a start's recorded end is the ftb_upd_pft_addr_u0 of its
  last update since that allocation; the split end is the PC plus

## Decisions made not explicit in the prompt
- PROVISIONAL: the index and tag split. FTB index VA[13:5] XOR
  (VA[4:1] << FTB_SOFF_SHIFT), FTB_SOFF_SHIFT = FTB_IDX_BITS -
  FTB_BR_POS_BITS = 5; tag {VA[39:14], VA[4:1]}. Reason: the starts of
  one region go to 16 different sets (a set holds one start per
  region); folding the offset into the TOP index bits makes two starts
  at different offsets share a set only when their regions differ in
  VA[13:10] (1 KB or more apart), never adjacent regions, which a fold
  into the low bits would give; the region index of aligned starts is
  unchanged, so sequential code maps as before. XiangShan's choice
  (index from the bits just above the instruction offset, VA[9:1])
  puts every 32-byte-aligned start, the common case after a fall-
  through, in 32 of the 512 sets. Measured: R2b, TC20, and T2 (FTB
  evictions 15 -> 14 over all programs). uBTB the same with
  UBTB_SOFF_SHIFT = 2.
- PROVISIONAL: start-relative storage. Positions FTB_BR_POS_BITS (4),
  pftAddr from the start, PFTADDR_BITS = FTB_BR_POS_BITS + 1 = 5 (an end
  lies in (start, start + 34]); conditional targets from the branch PC
  and jump targets from the jump PC as before (O-1, 4.2), now computed
  from the start. Reason: with one start per entry a region offset is a
  constant, so region-relative storage costs a bit per field for
  nothing. The uBTB stores start-relative positions and pftAddr; its
  targets stay displacements from the block start (its stated
  divergence from the FTB, kept: changing it moves the reach window of
  the uBTB, which tb_ubtb TC09 pins).
- PROVISIONAL: the window mask (R-1), the hiding of a field past the
  visible jump, and the read compaction (O-3b) are removed in both. A
  per-start entry holds only its own start's branches, in position
  order, so there is nothing to hide; br1 is reported only with br0
  (the compaction invariant). Storage order (O-3a) is kept, enforced by
  the update's sort.
- PROVISIONAL: the end. A conditional's update end (the block's
  predicted end) is not written; the end is the natural end (start +
  FTB_BLOCK_BYTES) on allocation, a written jump's resolved end, or a
  split point, and it only moves down. Reason: order independence that
  survives stale updates. With the update's end written, a resolution
  from a block predicted before the split (common in a loop with
  several iterations in flight) restores start + 32, the split branch
  goes unpredicted until it resolves again, and the uBTB and FTB ends
  disagree in the meantime. Cost: an end shortened by code that later
  changes (self-modifying code, two address spaces with one VA) stays
  short until the entry is evicted; the cost is an extra block, not a
  wrong prediction.
- PROVISIONAL: a resolution at a stored position of the other kind
  (a conditional where the jump is stored, or the reverse) replaces
  that field; a jump before the stored jump replaces it and removes the
  conditionals after it.
- PROVISIONAL: the RAS fix (Problem 4). A RETURN commit whose snapshot
  TOSR equals its snapshot BOS (the block left the stack empty) leaves
  BOS where it is. The rejected alternatives: a range-based empty test
  (TOSR older than BOS in allocation order), already rejected by BP-138
  because the sentinel skip breaks it; and never moving BOS on a pop
  commit (XiangShan), which breaks ras.sv's TOSR == BOS rule when a pop
  commits below a committed push.
- The past-the-end test uses the bounded end (eff_end), so an out-of-
  bounds stored end does not freeze the entry (Problem 4).
- ftb_upd_br_idx_u0 and ubtb_upd_t.br_idx are no longer read (a field
  is named by its position). The ports and the struct member stay
  (ports unchanged, as ruled); they are named here for the PA.
