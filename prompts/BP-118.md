# Task Overview

Two rulings from session-075, built together.

TD#113. The FTQ entry's fall-through, pft_addr, is written once at p1
and never corrected. A new port on the p2 block-scalar group,
bpu_blk_pft_p2, carries the corrected value and the FTQ rewrites the
field from it for every valid p2 block.

TD#134. The IFU applies a flush only by clearing everything, and is
legal only with nothing outstanding. IFU-28 to IFU-32 replace that
stub: blocks older than the flush index survive, and requests
already in flight to the L1I and the ITLB are retired cleanly. This
is what lets the IFU be connected to the FTQ redirect path.

## Background
TD#113. bp_ftq_entry_t.pft_addr is written once at p1 from
bpu_pred_pft_p1. The 4a groups carry bp_ftq_slot_t only, so nothing
corrects it. On a uBTB miss the p1 value is the lookup PC plus
FTB_BLOCK_BYTES, a full block, and when the FTB ends the block
earlier the entry keeps the wrong end. Section 4 names two consumers
harmed by it: the not-taken arm of the successor selection, and the
RAS return address. Ruled session-075 (Jeff): bpu_blk_pft_p2 joins
the 4c group beside bpu_blk_ras_p2, valid under bpu_blk_val_p2 for
every valid p2 block, and its value is the not-taken term the cluster
already uses for its p2 successor in the section 6 redirect
comparison. One source for both, so the entry and the redirect
decision cannot disagree.

TD#134. As built by BP-116 a flush clears all IFU state, and
ifu_assert U3 fires if one arrives with an L1I identifier or an ITLB
lookup outstanding. Clearing all is wrong: ftq_decisions.md 5.5 R1
does not rewind fetch_ptr or xlate_ptr past an entry older than the
flush index F, so a block older than F that the IFU drops is never
presented again. Ruled session-075 (Jeff), IFU-28 to IFU-32:
survival measured from ftq_ifu_commit_ptr; killed L1I identifiers
whose responses are discarded; a shared line buffer slot that
survives if any block it serves does; dead ITLB lookups that are
drained before translation restarts; and no writeback for a dropped
block after the flush cycle, which is what keeps the one-bit
generation tag sufficient. Since BP-117 a predecode redirect flushes
at K+1, so the block that caused it survives its own flush.

## Binding Previous Decisions
- bpu_blk_pft_p2 takes its value from the same net the p2 redirect
  comparison uses for the not-taken successor. Do not derive it a
  second time.
- No package declaration change. bp_ftq_entry_t already has pft_addr.
- The FTQ side of the IFU boundary does not change for TD#134.
- TD#135 (uncached) and TD#136 (maintenance) stay stubbed. A request
  presented in a flush cycle is still ignored (IFU-20).

Problem 1. TD#113, the corrected fall-through.
  bp_cluster drives bpu_blk_pft_p2 on the 4c group. The FTQ writes it
  into pft_addr of the named entry for every valid p2 block, with the
  same stale-response drop as bpu_blk_ras_p2.
  Accept:
  - Results Capture names the net that feeds bpu_blk_pft_p2 and
    states its value when the FTB answers and when it does not, read
    from the RTL;
  - checks, each shown failing on the pre-edit tree, that the
    entry's pft_addr after p2 is the FTB fall-through when the FTB
    ends the block earlier than a uBTB miss assumed, and is the p1
    value when the FTB does not answer;
  - a check that a p2 write for a squashed entry does not land;
  - for each consumer section 4 names, the successor re-derivation
    and the RAS commit return address: state whether it reads
    pft_addr, and if it does, a check that it now sees the corrected
    value. If it does not, report what it reads instead.

Problem 2. TD#134, the flush with requests in flight.
  Build IFU-28 to IFU-32 and remove the stub they replace.
  Accept:
  - IFU-28: with blocks older than F held in each IFU structure,
    a flush keeps them and they are delivered and written back in
    order; blocks at or after F are dropped. Cover an index wrap
    and RC_UNSPEC (F = commit_ptr). Shown failing on the pre-edit
    tree;
  - IFU-29: L1I responses for dropped blocks, including out of order,
    reach neither the ibuf nor the writeback, and every identifier
    and line buffer slot is free once the responses are in;
  - IFU-30: a line buffer slot shared by a surviving and a dropped
    block keeps the surviving block;
  - IFU-31: ITLB responses for a dropped block are discarded, and
    translation of a new block starts the cycle after the last dead
    lookup answers and not before. Show this with dead responses
    returned late and out of order. The wait itself is the ITLB's
    miss latency and is not measured here;
  - IFU-32: an assertion that no writeback for a dropped block is
    presented after the flush cycle;
  - the predecode case: after a predecode redirect at K+1, block K
    is not dropped by its own flush;
  - every new or changed property shown to fire under fault
    injection on a scratch copy. U3 is removed or restated, and
    Results Capture says which.
  If the testbench's L1I or ITLB models cannot hold a response back
  or return responses out of order, extend them; the cases above are
  not reachable otherwise.
