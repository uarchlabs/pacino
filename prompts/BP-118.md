# Task Overview

The front end, end to end, in one task.

First the two FTQ/IFU fixes the integration needs. TD#113: the FTQ
entry's fall-through is written once at p1 and never corrected; a
new p2 port carries the corrected value. TD#134: the IFU applies a
flush by clearing everything and is legal only with nothing in
flight; blocks older than the flush index must survive and
in-flight requests must be retired cleanly.

Then the three units that do not exist -- the instruction buffer,
the ITLB and the PMP/PMA checker -- decode moved onto the IFU's
packet (TD#143), two session-075 rulings checked against built RTL,
and the front-end top connecting BPU, FTQ, IFU, L1I, ITLB, ibuf and
decode, with a testbench that fetches and decodes real programs
through it.

Deliberately large: one task, to test how far one IA session goes.
Written as BP-118 and BP-119 and merged before either ran.

Each piece is fully specified and can be built from its documents.

## Background
TD#113. bp_ftq_entry_t.pft_addr is written once at p1 from
bpu_pred_pft_p1 and nothing corrects it. On a uBTB miss the p1 value
is the lookup PC plus FTB_BLOCK_BYTES, and when the FTB ends the
block earlier the entry keeps the wrong end. Ruled session-075:
bpu_blk_pft_p2 joins the 4c block-scalar group beside
bpu_blk_ras_p2, valid for every valid p2 block, and its value is the
not-taken term the cluster already uses for its p2 successor in the
section 6 redirect comparison (ftq_bpu_interfaces.md 4c).

TD#134. As built by BP-116 a flush clears all IFU state, and
ifu_assert U3 fires if one arrives with an L1I identifier or ITLB
lookup outstanding. Clearing all is wrong: ftq_decisions.md 5.5 R1
does not rewind fetch_ptr or xlate_ptr past an entry older than the
flush index F, so a block older than F the IFU drops is never
presented again. Ruled session-075: IFU-28 to IFU-32
(ifu_decisions.md 6.1). Since BP-117 a predecode redirect flushes at
K+1, so the block that caused it survives its own flush.

The rest. The ibuf, ITLB and PMP/PMA checker have documents and no
RTL. Decode still takes predecode_pkt_t, which TD#143 retires. No
front-end top exists; the BPU, FTQ and IFU have only run against
testbench models of each other. Session-075 ruled every open item
these need: ibuf not banked, one read ready, cleared by the backend
redirect valid (IBUF-U1, IBUF-12, IBUF-13); ITLB tracker depth a
parameter, default 1 (ITLB-15), PTE permissions checked on every
hit (ITLB-16), G-stage permissions in the walker (MMU-26), a CSR
input group (ITLB-17, MMU-11a), the invalidate port list proposed
here (ITLB-14); the PMA region table with main memory 0x8000_0000 to
0xF_FFFF_FFFF (MMU-15a); decode DCD-17 to DCD-20; RETURN_CALL
training uBTB, FTB and RAS (fe_decisions.md 7.2); the loop predictor
overriding only a slot the uBTB supplied (ftq_bpu_interfaces.md 4);
the top's input groups and the L1I's emitted path (FE-20, FE-21).

Problem 1. TD#113, the corrected fall-through.
  bp_cluster drives bpu_blk_pft_p2 on the 4c group. The FTQ writes it
  into pft_addr of the named entry for every valid p2 block, with the
  same stale-response drop as bpu_blk_ras_p2.
  Accept:

    states its value when the FTB answers and when it does not, read
    from the RTL;
  - checks, each shown failing on the pre-edit tree, that the
    entry's pft_addr after p2 is the FTB fall-through when the FTB
    ends the block earlier than a uBTB miss assumed, and is the p1
    value when the FTB does not answer;

  - for each consumer section 4 names, the successor re-derivation
    and the RAS commit return address: state whether it reads
    pft_addr, and if it does, a check that it now sees the corrected
    value. If it does not, report what it reads instead.

Problem 2. TD#134, the IFU flush with requests in flight.
  Build IFU-28 to IFU-32 and remove the stub they replace.
  Accept:
  - IFU-28: with blocks older than F held in each IFU structure,
    a flush keeps them and they are delivered and written back in
    order; blocks at or after F are dropped. Cover an index wrap
    and RC_UNSPEC (F = commit_ptr). Shown failing on the pre-edit
    tree;
  - IFU-29: L1I responses for dropped blocks, including out of order,
    reach neither the ibuf port nor the writeback, and every
    identifier and line buffer slot is free once they are in;
  - IFU-30: a line buffer slot shared by a surviving and a dropped
    block keeps the surviving block;
  - IFU-31: ITLB responses for a dropped block are discarded, and
    translation of a new block starts the cycle after the last dead
    lookup answers and not before. Show this with dead responses
    returned late and out of order. The wait itself is the ITLB's
    miss latency and is not measured here;
  - IFU-32: an assertion that no writeback for a dropped block is
    presented after the flush cycle;
  - the predecode case: after a predecode redirect at K+1, block K
    is not dropped by its own flush;
  - U3 removed or restated, and Results Capture says which.
  If tb_ifu's L1I or ITLB models cannot hold a response back or
  return responses out of order, extend them.

Problem 3. The instruction buffer, rtl/core/frontend/ibuf.
  Build it from ibuf_decisions.md and ifu_ibuf_interfaces.md.
  Accept, each with a check in its own testbench:
  - a block is accepted whole, and ready rises only with 16 entries
    free whatever the block's enable mask holds (IB-6, IBUF-4);
  - enabled slots are compacted on write, in order (IBUF-3);
  - an empty buffer bypasses a write to the read port in the same
    cycle (IBUF-7);
  - the read port presents up to 8 valid entries from the head in
    order, and one ready dequeues all of them (IBUF-9, IBUF-12);
  - the backend redirect valid clears it, and nothing else does
    (IBUF-8, IBUF-13);
  - depth is a parameter, default 64 (IBUF-11), with full, wrap and
    a write and a read in one cycle covered.

Problem 4. The PMP/PMA checker, rtl/mmu/pmp.
  Build the one checker of MMU-10a, with MMU-11, MMU-11a and MMU-12
  to MMU-15a.
  Accept:
  - PMP: TOR and NAPOT matching, the lowest-numbered matching entry
    decides, the L bit, M-mode with no match allowed, S and U with
    no match denied when any entry is implemented. State the
    reference used for each rule; tools/spike/ is permitted;
  - PMA: the default region table of MMU-15a classifies addresses
    inside and outside main memory correctly, at both ends of the
    range;
  - the effective type combines the region with a PBMT input, most
    restrictive wins (MMU-U6);
  - the region table and the PMP entry count are parameters.

Problem 5. The ITLB, rtl/mmu/itlb.

  Accept, each with a check:

  - non-blocking: hits continue while a walk is outstanding
