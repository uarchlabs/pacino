# Task Overview

The front end, end to end, in one task.

First the two FTQ/IFU fixes the integration needs. TD#113: the FTQ
entry's fall-through is written once at p1 and never corrected; a
new p2 port carries the corrected value. TD#134: the IFU applies a
flush by clearing everything and is legal only with nothing in
flight; blocks older than the flush index must survive and
in-flight requests must be retired cleanly.

Then the three units that do not exist -- the instruction buffer,
the ITLB and the PMP/PMA checker -- decode moved onto the IFU's
packet (TD#143), two session-075 rulings checked against built RTL,
and the front-end top connecting BPU, FTQ, IFU, L1I, ITLB, ibuf and
decode, with a testbench that fetches and decodes real programs
through it.

Deliberately large: one task, to test how far one IA session goes.
Written as BP-118 and BP-119 and merged before either ran.

## Background
TD#113. bp_ftq_entry_t.pft_addr is written once at p1 from
bpu_pred_pft_p1 and nothing corrects it. On a uBTB miss the p1 value
is the lookup PC plus FTB_BLOCK_BYTES, and when the FTB ends the
block earlier the entry keeps the wrong end. Ruled session-075:
bpu_blk_pft_p2 joins the 4c block-scalar group beside
bpu_blk_ras_p2, valid for every valid p2 block, and its value is the
not-taken term the cluster already uses for its p2 successor in the
section 6 redirect comparison (ftq_bpu_interfaces.md 4c).

TD#134. As built by BP-116 a flush clears all IFU state, and
ifu_assert U3 fires if one arrives with an L1I identifier or ITLB
lookup outstanding. Clearing all is wrong: ftq_decisions.md 5.5 R1
does not rewind fetch_ptr or xlate_ptr past an entry older than the
flush index F, so a block older than F the IFU drops is never
presented again. Ruled session-075: IFU-28 to IFU-32
(ifu_decisions.md 6.1). Since BP-117 a predecode redirect flushes at
K+1, so the block that caused it survives its own flush.

The rest. The ibuf, ITLB and PMP/PMA checker have documents and no
RTL. Decode still takes predecode_pkt_t, which TD#143 retires. No
front-end top exists; the BPU, FTQ and IFU have only run against
testbench models of each other. Session-075 ruled every open item
these need: ibuf not banked, one read ready, cleared by the backend
redirect valid (IBUF-U1, IBUF-12, IBUF-13); ITLB tracker depth a
parameter, default 1 (ITLB-15), PTE permissions checked on every
hit (ITLB-16), G-stage permissions in the walker (MMU-26), a CSR
input group (ITLB-17, MMU-11a), the invalidate port list proposed
here (ITLB-14); the PMA region table with main memory 0x8000_0000 to
0xF_FFFF_FFFF (MMU-15a); decode DCD-17 to DCD-20; RETURN_CALL
training uBTB, FTB and RAS (fe_decisions.md 7.2); the loop predictor
overriding only a slot the uBTB supplied (ftq_bpu_interfaces.md 4);
the top's input groups and the L1I's emitted path (FE-20, FE-21).

## Assumptions made not explicit in the prompt
- An L1I request already presented to the L1I is not withdrawn by a
  flush (IF-4 holds it to acceptance); a dropped block's request is
  kept presented and its response discarded.
- The straddle register survives a flush only when the block after
  its setter survives.
- The IFU applies no flush transfer in a flush cycle: a surviving F3
  block is offered from the next cycle.
- tb_fe_top: the backend's predicted successor of a retired branch is
  the next instruction delivered; a JAL's successor must be its
  target.
- The commit watermark after a backend redirect is the entry before
  the restart point (K for _self clear, K-1 for _self set).
- RVA23_ENABLE for decode; sc_enable 1, ftb_fastpath_en 0 and aging
  off in tb_fe_top.
- Agent assumptions: CSR MODE 0 = Bare, nonzero = Sv39/Sv39x4; priv
  encoding 0 U, 1 S, 3 M; reserved PBMT treated as IO; PMA bounds
  granule aligned; A bit is the walker's; a faulting decode slot
  carries valid and instr only; a faulting slot neither raises nor
  seeds vtype_hazard; the ibuf clear cycle presents nothing.
