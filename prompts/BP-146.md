# Task Overview
The second of three tasks that build pacino's mode set (Jeff,
session-085; mmu_decisions.md MMU-20, MMU-32). BP-145 set the widths.
This task builds the walker in every mode:
1. The CSR packages accept satp and vsatp MODE Sv48 and Sv57 and
   hgatp MODE Sv48x4 and Sv57x4 (csr_decisions.md 3, CSR-5).
2. The walker walks 3, 4 or 5 levels as the mode says, at both
   stages, with the x4 root and the per-mode GPA bound (MMU-32,
   MMU-28), and returns the 512 GiB and 256 TiB sizes (IL-7).
3. A page-table builder for testbenches maps a page in any mode, so
   tests stop writing table entries by hand.

The ITLB is NOT in this task: it still checks the Sv39 address rule
and treats size codes 3'b1xx as reserved. The next task builds the
ITLB's modes (ITLB-3, ITLB-18), moves the translated regression tests
to Sv57 and writes the weekly all-modes regression.

## My Assessment

A check is necessary to determine if the specifications state what is the
documented behavior when an unsupported mode is written to the CSR:

Per RISC-V Instruction Set Manual, Volume II: Privileged Architecture, when an
attempt to write an unsupported MODE value to satp the whole register write is
ignored, the register does not change.

  An unsupported MODE value never reaches the walker, because the CSR file
  applies CSR-5. 

The exception allowed in 'debug mode'. There is no defined mechanism specified
for this. Pacino will implement a 'control bit in a (new) Pacino debug support
csr that circumvents this rule for silicon brinup purposes.

Summary:

    except an x4 root, which is indexed by eleven.
  - A leaf may be at any level, and a misaligned superpage is a page
    fault, or a guest-page fault at the G-stage.
  - The two stages take their modes independently, both sampled when
    the walk starts (MMU-24a). Any pair is legal.
- THE GPA BOUND (MMU-28, MMU-20). A GPA with a bit set at or above
  the hgatp mode's width is a guest-page fault: 41 bits for Sv39x4,
  50 for Sv48x4, 59 for Sv57x4. This covers the G-stage-only fetch
  address, the vsatp root, and a VS-stage PTE's GPA.
  - Each width is an architectural constant in bp_defines_pkg.sv,
    named like SV39X4_GPA_WIDTH, never derived from GPA_WIDTH.
  - The walker checks that GPA_WIDTH is at least the widest of them.
- SIZES (IL-7, MMU-27). 3'b100 is 512 GiB and 3'b101 is 256 TiB;
  3'b11x stays reserved. A two-stage size is the smaller of the two

- NAPOT (MMU-U7). N=1 is defined only at level 0, 64 KiB, in every

### Problem 3: the builder (rtl/mmu/ptw/tb/pt_build_pkg.sv)
Interface:
- pt_image: put(a, d), has(a), get(a), pop(a, d). One image per test,
  shared by all stages. It holds every word written, keyed by
  supervisor physical address, plus a queue of writes in order.
- pt_stage: new(name, img, MODE, x4, root, pool_base, pool_top).
  - set_gstage(g): a VS stage whose tables are guest physical.
  - set_back(base, top, flags): G-stage pages that back VS table pages
    (default flags D A U X W R V).
  - set_soft(1): conflicts are counted in n_conflict, not fatal.
  - idx(addr, level).
  - map(addr, level, pte): returns the supervisor address of the PTE it
    wrote.
  - pte_addr(addr, level).
  - xlate(gpa, ok): G stages only.
- Path: an empty slot gets a pool table and a V-only pointer. A pointer
  is followed. Anything else is a conflict. At the target level, an
  identical word is accepted and a different one is a conflict.
- Other misuse is always $fatal: a level above the root, an exhausted
  pool, a misaligned root (an x4 root must be 16 KiB aligned), or an x4
  GPA beyond the mode's width.
- VS stage: each guest table page is translated through the G stage's
  tables in the image. An unmapped guest page is mapped by the G stage
  at level 0 to the next backing page.
- No method calls itself, directly or through another object. map_phys
  and map_guest are separate loops so that Verilator never sees a
  recursive call.
How a testbench gets the words: it drains the queue into its own memory
model with "while (img.pop(a, d)) write(a, d)". tb_ptw does this in
bsync() into its word store, with a $fatal if an address is beyond
PA_WIDTH. tb_fe_top can drain into its shared image the same way. The
package never names a memory model, so it needs no change for that.
The builder sees only the words it wrote. A testbench keeps hand-written
words apart from builder regions; tb_ptw puts the builder at
0x9000_0000 and up.
Makefile: pt_build_pkg.sv added to TB_PKG_SRCS. New target
lint_pt_build_pkg, added to REGRESS_TARGETS and all. It uses
SIM_EXTRA_FLAGS (-Wno-DECLFILENAME) because its classes are not named
for the file.
