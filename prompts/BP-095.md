# Task Overview

Nine files under rtl/core/frontend/bpu/tb/ contain no $fatal
anywhere. A testbench with no fatal exit reports success to
make no matter what it finds.

  tb_ittage_cntrl.sv   sim_ittage_cntrl   claims 147 pass
  tb_ittage.sv         sim_ittage         claims 211 pass
  tb_ittage_table.sv   sim_ittage_table   claims  32 pass
  tb_tage_manual.sv    sim_tage_manual    claims   3 pass
  tb_tage_tasks.sv     sim_tage_tasks     claims all pass
  tage_assert.sv       tage_assert_bind.sv
  ittage_assert.sv     ittage_assert_bind.sv

tb_ittage_cntrl.sv line 1660 is confirmed: the failure exit is
$finish(1), which Verilator v5.048 turns into exit 0. The other
four testbenches have no fatal exit at all and their
termination path is unknown. The four assert files are bound
SVA modules and how a failing assertion propagates to the exit
code under this project's flags is also unknown.

This is the third instance of the same defect. BP-086 found it
in tb_ubtb and fixed it. BP-094 found it in tb_tage and fixed
it, and reported that until the fix neither its new test nor
the ninety-odd tests already in that file could block anything.

The consequence is retrospective. Every count those five
targets have contributed to PROJECT_STATUS came from a harness
that was never gated. The results are not necessarily wrong;
they are unenforced, and nobody has ever distinguished the two.
That is what this task settles.

READING THE CODE IS NOT PROOF. Every claim in this task about
whether a suite can fail must come from a run in which a check
was deliberately broken and the exit code observed.

## Background

Verilator v5.048 turns $finish(1) into exit 0. A testbench that
counts failures, prints them, and calls $finish returns success
to make. The target passes. The suite is decorative.

BP-086 found this in tb_ubtb, where a failing run had been
reporting a passing target. BP-094 found it in tb_tage the same
way -- by running the harness against deliberately broken RTL
and getting eleven printed failures with make exit 0.

Both times it was found incidentally, by a task that happened
to need a failing run for another reason. Nobody has swept for
it.

The ITTAGE unit is the exposure. PROJECT_STATUS records ITTAGE
as directed-validation-complete on 390 checks across three
targets, all three of which are on this list.
