## Background

bp_ftq_entry_t in the package is the flat, pre-dual-slot form: one
scalar target, br_type, taken, pred_src, and confidence per entry.
fe_decisions.md 4.1 defines the entry as block-scalar fields plus a
per-slot array, one entry per fetch block carrying NUM_PRED_SLOTS
predictions. The package has not been updated to match.

planning/interfaces/ftq_bpu_interfaces.md section 9 lists the
package changes required. This task applies them.

FTQ_CONF_BITS, GHIST_PTR_BITS, PHIST_PTR_BITS, FTQ_IDX_BITS,
VA_WIDTH, and NUM_PRED_SLOTS already exist in bp_defines_pkg.sv. No
new parameter is added.

## Binding Previous Decisions

- Packed-struct dimensions descend, [NUM_PRED_SLOTS-1:0]. Port
  dimensions ascend, [0:NUM_PRED_SLOTS-1]. The slot array is inside
  a packed struct, so it descends.
- bp_ftq_meta_t is carried per slot, but the array is declared at
  the port, not inside the struct. Same convention as bp_update_t.
  Do not add a slot dimension inside bp_ftq_meta_t.
- ftq_idx has already been removed from bp_redirect_t; the field is
  commented out in the current file. Do not re-add it and do not
  delete the commented line.
- bp_update_t is the FTQ-side resolved-branch record, not a port
  type. It is correct as written. Do not change its fields.
- BUG-006: build from the tree. If a Context Loaded path does not
  exist, STOP and report it.

## Specific Requirements

1. Read bp_structs_pkg.sv before editing.

2. Add bp_ftq_slot_t, declared immediately before bp_ftq_entry_t in
   the Top-level structs section:

```
  typedef struct packed {
    logic                      slot_valid;
    logic [VA_WIDTH-1:0]       target;
    bp_br_type_e               br_type;
    logic                      taken;
    bp_pred_src_e              pred_src;
    logic [FTQ_CONF_BITS-1:0]  confidence;
  } bp_ftq_slot_t;
```

3. Restructure bp_ftq_entry_t. Remove the scalar target, br_type,
   taken, pred_src, and confidence fields. Keep pc, branch_id, ras,
   ghist_ptr, phist_ptr, and valid. Add the slot array as the last
   field:

```
  bp_ftq_slot_t [NUM_PRED_SLOTS-1:0] slot;
```

4. Correct branch_id comments from "FTQ slot index" to "FTQ entry
   index" in bp_ftq_entry_t, tage_pred_meta_t, ittage_pred_meta_t,
   and bp_update_t. sc_pred_meta_t.branch_id carries no comment; add
   "FTQ entry index". This is TD-FE-5.

5. Change the bp_redirect_t header comment stage labels from s2/s3
   to p2/p3, and state that the struct is the per-slot payload with
   a scalar FTQ entry index alongside the array at the port.

6. Retarget the two enum header comments that name fields which
   moved: bp_br_type_e cites bp_ftq_entry_t.br_type and
   bp_pred_src_e cites bp_ftq_entry_t.pred_src. Both fields now live
   in bp_ftq_slot_t.

7. Update the bp_ftq_meta_t header comment to state it is carried
   per prediction slot with the array declared at instantiation.

8. Search the bpu unit for consumers of the removed scalar fields
