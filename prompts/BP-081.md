## Assumptions made not explicit in the prompt
- PC=0x182BC hashes T1-T4 to bank 0 row 175 with tag 0x30 (reused from
  the pre-existing, passing pred_strong_tst), so invalidating T2-T4 at
  [0][175] is sufficient to make T1 the sole provider on both slots.
- The 6b concat in the TD#88 formula assigned to the signed 5b field is
  intentional: the value range [-7,+7] fits and the top concat bit is
  redundant sign extension. An inline lint_off/on WIDTHTRUNC bracket was
  used so lint_tage_cntrl/lint_tage stay warning-free (those targets do
  not carry a project WIDTHTRUNC suppression).

## Decisions made not explicit in the prompt
- Update-side UAON gate keyed on tage_pred_weak. The old gate was
  "if (!tage_pred_strong)" where strong meant NOT WEAK, so it fired on a
  weak (boundary) prediction. With strong reconciled to {000,111}, the
  behavior-preserving equivalent (weak, medium, and strong CTRs all
  match the old outcome) is "if (tage_pred_weak)". Keying on the new
  strong flag instead would have wrongly fired UAON on medium CTRs;
  rt_ctr_rows7_8_tst (post-mux CTR=101 must suppress UAON) confirms this.

  upd_uaon_dec, uaon_row2..row5) previously relied on the default
  tage_pred_strong=0 to enter the UAON body; they now set
  tage_pred_weak=1 to represent the weak prediction that gates UAON.
  Round-trip (rt_*) UAON tests needed no change: they update using the
  DUT-captured meta, which now carries tage_pred_weak directly.
