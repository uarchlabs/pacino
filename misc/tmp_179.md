## 1. Requirement (Jeff, 2026-10-18)

Every branch is predicted, at every slot count. NUM_PRED_SLOTS sets how
many branches one prediction block can carry, which is how fast the
prediction pipeline fills the FTQ. It does not decide whether a branch
is predicted. The FTQ decouples prediction from fetch, so a block cut
early costs prediction bandwidth only.

This restates BP-128 D2 ("MUST BE FIXED", Jeff, session-078), which was
put ON HOLD and deferred to TD#179 together with the entry shape,
region sharing (TD#168) and the training point.

## 2. Current behavior (RTL, tree 0599061)

At NUM_PRED_SLOTS = 1 the second conditional of a block is never
predicted, and when it resolves it trains the table predictors with
the first conditional's metadata.

- bp_cluster.sv:1658. Slot gs reads FTB br0 when gs == 0, else br1. At
  one slot only br0 is read; the FTB br1 port is driven
  (ftb_cntrl.sv:690-695) and ignored.
- ubtb.sv:38-39. At one slot only the br0 field is reported.
- bp_cluster.sv:1041-1047, 1100-1112. The block cut of BP-138 D1
  (w_jmp_cut_p2) tests the jump field only. With a conditional in no
  slot, w_pft_p2 stays at the FTB's stored end, so the predicted path
  runs past the unslotted conditional as if it were not taken.
- ftq_resolve.sv:281-293, place_slot. A resolution whose position
  names no slot goes to the lowest slot free or at or after its
  position, else the LAST slot. At one slot, with slot 0 holding the
  first conditional at a lower position, the result is slot 0. The
  update then carries slot 0's table index, tag and metadata (BP-119:
  trained as a mapped branch, no R2 suppression), so TAGE, SC and LP
  write the second branch's outcome into the first branch's entries.
- ftb_decisions.md 3 states the split rule (block ends at the last
  branch the entry can hold) and records it as NOT BUILT at either slot
  count. At one slot a second conditional is "still never reported
  (BP-128 D2)".

## 4. Proposed rule

A prediction block ends at the PC of the first branch that no slot
carries, conditional or jump. The next block starts at that PC, the
FTB window from that start (4.6 R-1, O-3b) reports the branch first,
and it is placed in slot 0.

This is BP-138 D1 option b generalized from the jump to any branch.
At one slot it applies to a block's second conditional; at two slots
to a third conditional (the existing ftb_decisions.md 3 case, measured
as never occurring in tb_fe_top) and to a jump behind two conditionals
(already built).

## 5. Implementation options for the task

A. Cut at the cluster, p2 (recommended as the first step).
   bp_cluster forms a conditional cut beside w_jmp_cut_p2: a visible
   FTB conditional field with no slot sets w_pft_p2 to that branch's
   PC. At one slot the FTB br1 port already carries the field and its
   position. No FTB, uBTB, FTQ entry, package or port change, the same
   scope BP-138 kept. Cost, as BP-138 in fd04: the uBTB's p1
   fall-through still steps over the branch, so each cut block costs a
   p2 redirect until the uBTB learns the shortened end.

B. Split at update. FTB and uBTB updates write an end that stops at the
   held branches (ftb_decisions.md 3 as written). Removes the p2
   redirect of A. Interacts with the shared region entry (4.6, TD#168):
   BP-131 found a split end would differ from another start's recorded
   end in 228 of 228 one-slot cases, contention for the one pftAddr.
   Belongs with the entry-shape decision.

Either option still needs:

C. No training through another branch's slot. When place_slot returns
   a slot whose valid pos is not the resolved branch's pos, the slot's
   metadata describes a different branch. Form the uBTB and FTB updates
   only and suppress TAGE, SC, LP and ITTAGE, as R2 does for a br_type
   mismatch (ftq_resolve.sv header, ftq_entry_formats.md 3.1). This
   still applies after A or B: the first execution of a branch the FTB
   does not yet hold (BP-119) can land in an occupied slot at one slot.
   Report the count as a coverage point; with A or B in place it should
   fall to first executions only.
